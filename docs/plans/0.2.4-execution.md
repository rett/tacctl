# tacctl 0.2.4: execution breakdown (2026-10-09)

The work packages of `0.2.4-plan.md` (decisions D60-D76), for a coordinator to hand to subagents. Rules: subagents work in worktrees off the branch tip and never commit; no two packages that run in parallel own the same file; every package ends with its own acceptance checks green; the coordinator reviews, merges, renumbers CHANGELOG items, regenerates shared goldens once per merge and commits on request. Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides design.

Sizes: S ≈ ½ session, M ≈ 1 session, L ≈ 1½-2.

## Acceptance commands (from `CLAUDE.md`; every package runs the ones that apply)

```
make build
LANG=C.UTF-8 go test ./internal/...                      # internal/cli: setsid -w ... < /dev/null, a scratch GOCACHE
make lint GOLANGCI_LINT=<path to golangci-lint>          # includes tests/tools/no-private.sh and the man tests
make man                                                 # then check the generated blocks are what the code says
tests/bats/bats-core/bin/bats tests/integration/<file>.bats     # as user tester, after make build
tests/diff/run.sh --all --against 0.2.3                  # every difference @known 0.2.4 item N
tests/containers/hosts/run.sh ubuntu-noble tacplus       # once, after WP11.6 (the sudoers env_keep line changed)
```

- The lab switch: read-only by default; any change under `commit confirmed 2`, named `zz-tacctl-*`, removed before the package ends; `gotest*` accounts only; the dev server is the only AAA server the test logins use; never the production host or a production device.
- The test host: the coordinator's own account; snapshots before any tacctl change; nothing left behind.
- The lab WTI: the user operates it; the run sheet carries the revert step for every change and keeps a serial or second session open; the coordinator never connects.
- Run sheets, addresses and names stay outside the repo; fixtures are sanitised before they enter it.

## Review findings carried into WP11.6's second half (wiring)

From the Opus security review of `internal/askpass` (2026-10-09); the library findings were fixed in the package, these belong to the wiring:

- **The token never goes in sudo's argv.** `shell.go`'s `extraEnv` passes `sudo VAR=value …` arguments, which are world-readable in `/proc/<pid>/cmdline`. Put `TACCTL_ASKPASS` in the environment of the sudo process (`cmd.Env`) with `env_keep`, only on the lines that need it (`device config pull`, `ssh`), and have the root side read it once and unset it so its children do not inherit it.
- **`tacctl ssh` with a cached password** forces `StrictHostKeyChecking=yes` against the pinned known_hosts, `NumberOfPasswordPrompts=1`, and no `SendEnv *`/`ProxyJump` from the user's config reaching the askpass path (a hostile or redirecting hop is asked the same prompt).
- **The pull stores only a password it prompted for**, never one it read from the cache (the max lifetime must not be extendable by use).
- **Root-side pull process:** `PR_SET_DUMPABLE 0`; `devssh.PasswordSource` returns a `string`, so the zeroisation promise ends at the askpass boundary: say so in plan §6.
- **`New` is called only when the policy turns the cache on**; mlock failure means no cache and one clear line ("password cache unavailable: cannot lock memory").
