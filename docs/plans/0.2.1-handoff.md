## Done on `feature/0.2.1`

- **Parity fixes** (CHANGELOG 1-13).
- **Device registry, host-key pinning and the generated known_hosts.** `known_hosts` lives at `/var/lib/tacctl/ssh/known_hosts`.
- **Device scan/discover/check:** sightings from the tacquito journal (streamed) and the FreeRADIUS auth log.
- **tacquito patches:** 0003 adds the NAS address to the authentication lines; 0004 sends no server message on a failed authentication.
- **`tacctl ssh`:** login is always the caller, password only, only active tacctl users in the entry's scope, `--` before the target.
- **`tacctl shell`:**
  - `help` and the usage rows come from one source.
  - Tab (twice) lists names in columns; `?` shows help.
  - A list above 40 entries asks first, and long output is paged.
  - Without `ssh -t`, the shell prints a hint.
- **zsh/fish completion.**
- **Release binaries:** downloaded and verified with `ssh-keygen -Y` against `release/allowed_signers`, which holds the user's real key; otherwise built from source.
- **sudoers:** `SETENV` replaced by `env_keep` after the `SUDO_USER` finding, and `SUDO_USER` is checked against `SUDO_UID`.
- **Linux host account lifecycle:**
  - Removed users are deleted; the home is asked about, deleted with `--remove-home`, or kept.
  - Kept homes move to `/home/.tacctl-removed`.
  - No `--adopt`; tac-* groups are cleaned off unmanaged accounts.
  - Host addresses are recorded at enroll/sync, and a `login.defs` warning is printed.
  - `host target` changes an enrolled host's connection settings.
- **Console WP7.0:** `console.yaml`, the policy, the `tacctl console` verbs and `_console-policy`.
- **Console WP7.1:**
  - `tacctl-console` mode, the `-c` guard (exit 126), the `system-shell` builtin (superusers only by default), hardened `ssh` in a console session, session logging.
  - Superuser lines run plain `sudo`, which asks for the password; read-only and operator lines use `sudo -n`.
- **Live acceptance WP6.11** on the dev server, the test client and a Juniper switch passed; its two `device scan` blockers are fixed.

## Remaining, in order

A range change renumbers by offset. enroll/sync read the host's `/proc/self/uid_map` and refuse a host that cannot hold the range (unprivileged containers). Then verify everything and merge it into `feature/0.2.1`. It conflicts with nothing in the console code, but `config/linux/client-install.sh` is shared with step 3. The protocol is `TAC_PROTOCOL=3`.

3. **WP7.2 provisioning** (`docs/plans/operator-console-wp-console.md` §5.3):
   - The login shell is a 4th `TAC_USERS` field for the local target only; `TAC_PROTOCOL` becomes **4**.
   - The `tac-console` group, the `/etc/shells` line, and the sshd drop-in (`Match Group tac-console`) validated with `sshd -t`, rolled back on failure, then reloaded.
   - The drop-in sets `PubkeyAuthentication no`. It must also close the **internal-sftp gap**: `ForceCommand /usr/local/bin/tacctl-console` and `DisableForwarding yes` in the match block. With `ForceCommand`, the console must read `SSH_ORIGINAL_COMMAND` for its `-c` guard.

4. **WP7.3 docs.** Also rewrite the usage blocks whose flags are described only in running text (for example `device add --vendor` or `device list`'s switches) as one line per option, so `?` shows a description for every flag.

The user signs `SHA256SUMS` with the passphrase-protected key: `ssh-keygen -Y sign -f ~/.ssh/tacctl-release -n tacctl-release dist/release/SHA256SUMS`.

## Working rules (unchanged)

- Subagents never commit. The coordinator commits when lint and tests are green. Push only when the user asks.
- No polling loops. Never `pkill -f` or `pgrep -f` with a pattern that also appears in your own command line.
- Every test sandboxes host paths.
- No private names in repo files: no host names, addresses, user names, home paths or domains. Use "the dev server", "the test client", "the production host", `example.*`. `make lint` runs `tests/tools/no-private.sh`. In a cloud session the untracked private-patterns file (`~/.config/tacctl/private-patterns`) is absent, so only the generic checks run; be careful by hand.
- Never anything against the production host. Live tests (WP7.4, and checking the UID renumber on the dev server and test client) need the user's own machine. A cloud session cannot reach those hosts or run the rootless-podman containers. Do code, unit, bats and docs work there; leave live and container runs for a local session.
- Live-test reminder for the renumber: the first sync renumbers the dev server's map (it keeps a `.pre-renumber-*` copy) and the hosts' accounts. A user logged in during that sync is skipped and retried later.
