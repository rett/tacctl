## 0. Summary

- **Goal:** the best block a person can paste into a device. Today `device config show` prints the fresh-device, whole-scope walkthrough [V: `juniper.template`, `tests/fixtures/golden/juniper-lab.conf`]: it starts with `delete system authentication-order`, prints every section with generic Step 1-8 comments, prints the shared secret, and knows nothing of what the device already runs. 0.2.4 added the pull and the per-section diff [V: `devconf.Compare`]. 0.2.5 adds **`tacctl device config plan`**: for a device that has been pulled, exactly the statements that take it from what it runs to what tacctl renders, in the right order, wrapped in the safe Junos procedure (private candidate, compare, check, confirmed commit, a verification from a second login and from the tacctl server, the confirming commit, and the way back out), with the device's own extra statements listed as kept, secrets handled by rule, and the sections the caller's class cannot change named.
- **Shape:** `show` stays the fresh-device walkthrough; `plan` is the delta (D94). The block is one text in a fixed order (D95); the wrapper and the pre-checks are the human version of the deferred apply transaction (D96); lock-out safety is by construction and by refusal (D97); secrets by the 0.2.4 rule (D98); three formats and files (D99); Cisco as the same delta, marked not lab-tested (D100); WTI waits for its own release (D101); the planner of the deferred plan is the engine (D102); tests without a device apply (D103); tiers, audit, settings, docs and `rollback 0.2.4` (D104, D105).
- **Order:** the lab check (WP13.0: private loads of emitted blocks on the lab switch, nothing committed) runs first and in parallel with the planner package; every offline package has a fallback for each [L] item.
- **Size:** 9 packages, ≈ 7-9 sessions, ≈ 4,000-5,000 lines. `--wrapper replace`, then the Cisco emitter, then `--json` and `--out-dir` are cut first if the release grows (§10).

## 1. Goals and non-goals

### Goals

1. **`device config plan`** (D94, D95): per device, from the last pull (`--pull` first), the statements and the procedure, for an engineer (own scopes) and a superuser alike.
2. **Lock-out safety by construction** (D97): order, never an empty authentication order, the confirmed commit as the only commit, the lo0 application never emitted, warnings and refusals where a block could cut the person off.
3. **Secrets** (D98): pasted when the device lacks them, never printed when present, `--secrets` and `--no-secrets`.
4. **Formats** (D99): the annotated block, a plain `load set` file, `--json`, `--section`, a selection with a cover summary, `--out`/`--out-dir` at 0600.
5. **Cisco** (D100, D106, D107): the same delta in IOS lines on the live IOS 12.4 findings; a line-by-line wrapper with a `no`-line back-out by default, the timed `configure replace` path as `--wrapper replace`; the AAA lock-out guards; the stored forms handled.
6. **Verified without a device apply** (D103): planner goldens, an in-memory property test, bats, and private loads on the lab switch.
7. **`tacctl rollback 0.2.4`** (D105) for the new key and the sudoers text.

### Non-goals (0.2.5)

- Writing to a device from tacctl: no apply, no enable-netconf, no `devapply` transaction, no fake-device configuration model (all in `apply-deferred.md`).
- WTI blocks (D101: 0.2.6, with the WTI read).
- Emitting `breakglass` (placeholder hash, the login path of last resort), `netconf` (the walkthrough's commented step), the lo0 application of the filter, `system root-authentication`, `system services ssh`, `groups`, `apply-groups`: never, whatever flag is given.
- Pruning foreign statements in a managed hierarchy (D102 keeps them, listed); a `--prune` stays a backlog idea.
- A rollback verb: the block carries the back-out procedure; `device config pull` records the state.
- Per-device source address (backlog §0b, parked): a configured one is a kept line.

| **D94** | **Shape: `device config show` stays the fresh-device walkthrough; a new verb `device config plan` emits the per-device delta from the last pull.** `tacctl device config plan (<name>… \| --all \| --scope <s> \| --vendor cisco\|juniper \| --stale) [--pull] [--section <list>] [--secrets \| --no-secrets] [--plain] [--json] [--out <file> \| --out-dir <dir>] [--from <address>] [--server …] [--source …]`. The delta is computed from the stored sections of the last pull [V: `Store.Sections`] against today's rendering, with the pull's time, user, transport and age in the header; a device never pulled is refused with `tacctl device config pull <name>` (or `--pull`, which reads first with the pull's options and then plans from what it read); a pull older than `stale-days` is a warning in the header, not a refusal. The two verbs relate as the header of each says: `show` is for a device that has nothing of tacctl yet (or that nobody has pulled), `plan` for one that has been read; `show`'s header gains one line naming `plan`. The same block for an engineer and a superuser: the rendering does not depend on who asks [V: `newManagedRender`], the engineer's selection is their own scopes, and the sections their Junos class cannot commit are named in the header with the bit (D97). *Alternatives:* a `--delta` mode on `show` (two outputs of opposite assumptions behind one verb); `--paste` on `diff` (a diff is a report, a plan is a procedure; the audit lines differ); replacing the walkthrough (a fresh device has no pull to plan from). | recommended |
| **D95** | **The block, in order, for Junos** (§3 shows one): (1) **header** comments: the device, scope, vendor and protocol; what it is based on (the pull's time, user, transport, age, whether the login could see secrets; the rendering's time; tacctl's version); the sections with their statement counts, the sections with no change, the sections not planned and why (`netconf`, `breakglass`: the walkthrough's steps), the kept count; the sensitivity line when the block holds a secret; the class note of D97 for an engineer. | **D96** | **The wrapper: `configure private`, lines pasted into configuration mode, one `commit confirmed`, the confirmation only after the verification.** `configure private` because another administrator's uncommitted shared work is neither committed nor discarded by the person [S: private isolation]; `configure exclusive` is named in the block as the choice when the person wants to block others for the window, never the default. ## 10. Risks

1. **The block deletes something it should not.** Mitigation: the ownership tables are data with a test per row; every `delete` is shown with its section's reason; the property test proves convergence on every fixture; Opus reviews the planner; the lab check loads real blocks without committing.
2. **A person pastes into the wrong device.** Mitigation: the header and the first pre-check name the device; one block per device, never a combined one; `--out-dir` names files by device.
3. **The wrapper's commit lines are written from the reference** (L3 not run). Mitigation: the 0.2.4 spike confirmed CLI `commit confirmed` and its expiry [S: (d)]; the comment syntax is the reference's; the release notes say what was not lab-run; a go-ahead can close it before the release.
4. **The engineer's class note is wrong** (L1). Mitigation: a note, not a refusal; L1 runs first.
5. **Size.** `--wrapper replace`, then the Cisco emitter, then `--json` and `--out-dir` are cut first; the Junos block, `--plain`, `--secrets`/`--no-secrets`, `--out`, the property test and `rollback 0.2.4` are not cuttable.
6. **Shared files** (`device_config.go`, `tier.go`, `ios.go`, docs, goldens): serialised in the execution plan.
7. **A Cisco block that locks the person out.** Mitigation: the AAA unit with `aaa authorization exec` in the same paste (D106 (i), tested by construction), the back-out that restores the vty login methods (D106 (ii), a refusal without the data), the enable-secret warning, the second privilege-15 terminal in the pre-checks, C2 on the lab router before the release.
8. **Stored forms differ on other IOS trains.** Mitigation: the tolerance rules are data with a fixture each; an unknown form is a `+` or `-` the person reads, never a `no` the block types; the header names the one image tested.
