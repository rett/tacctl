## 0. Summary

- **Goal:** the best block a person can paste into a device. Today `device config show` prints the fresh-device, whole-scope walkthrough [V: `juniper.template`, `tests/fixtures/golden/juniper-lab.conf`]: it starts with `delete system authentication-order`, prints every section with generic Step 1-8 comments, prints the shared secret, and knows nothing of what the device already runs. 0.2.4 added the pull and the per-section diff [V: `devconf.Compare`]. 0.2.5 adds **`tacctl device config plan`**: for a device that has been pulled, exactly the statements that take it from what it runs to what tacctl renders, in the right order, wrapped in the safe Junos procedure (private candidate, compare, check, confirmed commit, a verification from a second login and from the tacctl server, the confirming commit, and the way back out), with the device's own extra statements listed as kept, secrets handled by rule, and the sections the caller's class cannot change named.
- **Shape:** `show` stays the fresh-device walkthrough; `plan` is the delta (D94). The block is one text in a fixed order (D95); the wrapper and the pre-checks are the human version of the deferred apply transaction (D96); lock-out safety is by construction and by refusal (D97); secrets by the 0.2.4 rule (D98); three formats and files (D99); Cisco as the same delta, marked not lab-tested (D100); WTI waits for its own release (D101); the planner of the deferred plan is the engine (D102); tests without a device apply (D103); tiers, audit, settings, docs and `rollback 0.2.4` (D104, D105).
- **Order:** the lab check (WP13.0: private loads of emitted blocks on the lab switch, nothing committed) runs first and in parallel with the planner package; every offline package has a fallback for each [L] item.
- **Size:** 7 packages, ≈ 6-8 sessions, ≈ 3,500-4,500 lines. The Cisco emitter, `--json` and `--out-dir` are cut first if the release grows (§10).

## 1. Goals and non-goals

### Goals

1. **`device config plan`** (D94, D95): per device, from the last pull (`--pull` first), the statements and the procedure, for an engineer (own scopes) and a superuser alike.
2. **Lock-out safety by construction** (D97): order, never an empty authentication order, the confirmed commit as the only commit, the lo0 application never emitted, warnings and refusals where a block could cut the person off.
3. **Secrets** (D98): pasted when the device lacks them, never printed when present, `--secrets` and `--no-secrets`.
4. **Formats** (D99): the annotated block, a plain `load set` file, `--json`, `--section`, a selection with a cover summary, `--out`/`--out-dir` at 0600.
5. **Cisco** (D100): the same delta in IOS lines with the wrapper the references give, marked not lab-tested.
6. **Verified without a device apply** (D103): planner goldens, an in-memory property test, bats, and private loads on the lab switch.
7. **`tacctl rollback 0.2.4`** (D105) for the new key and the sudoers text.

### Non-goals (0.2.5)

- Writing to a device from tacctl: no apply, no enable-netconf, no `devapply` transaction, no fake-device configuration model (all in `apply-deferred.md`).
- WTI blocks (D101: 0.2.6, with the WTI read).
- Emitting `breakglass` (placeholder hash, the login path of last resort), `netconf` (the walkthrough's commented step), the lo0 application of the filter, `system root-authentication`, `system services ssh`, `groups`, `apply-groups`: never, whatever flag is given.
- Pruning foreign statements in a managed hierarchy (D102 keeps them, listed); a `--prune` stays a backlog idea.
- A rollback verb: the block carries the back-out procedure; `device config pull` records the state.
- Per-device source address (backlog §0b, parked): a configured one is a kept line.

| **D94** | **Shape: `device config show` stays the fresh-device walkthrough; a new verb `device config plan` emits the per-device delta from the last pull.** `tacctl device config plan (<name>… \| --all \| --scope <s> \| --vendor cisco\|juniper \| --stale) [--pull] [--section <list>] [--secrets \| --no-secrets] [--plain] [--json] [--out <file> \| --out-dir <dir>] [--from <address>] [--server …] [--source …]`. The two verbs relate as the header of each says: `show` is for a device that has nothing of tacctl yet (or that nobody has pulled), `plan` for one that has been read; `show`'s header gains one line naming `plan`. | **D96** | **The wrapper: `configure private`, lines pasted into configuration mode, one `commit confirmed`, the confirmation only after the verification.** `configure private` because another administrator's uncommitted shared work is neither committed nor discarded by the person [S: private isolation]; `configure exclusive` is named in the block as the choice when the person wants to block others for the window, never the default. | **D97** | **Lock-out safety by construction, and which of the deferred guards become warnings or refusals.** Order: `roles` before `aaa` (template users and classes exist before the authentication order can point at them), `snmp` next, `mgmt-acl` last (a change to a filter applied on lo0 is live at the commit). `system authentication-order` is emitted as `delete` + `set` on adjacent lines and never without the rendered method; the lo0 application is never emitted (the walkthrough's commented line stays the operator's step [V: D62 amendment]); the confirmed commit is the default wrapper (D96); the block never contains `commit` before `commit confirmed`, `load override`, `delete system services ssh`, nor anything of the never-emitted list. **Refusals to emit** (the section is left out with the reason in the header; the rest of the block stands): a statement that is inherited from a group (`inherited from group <g>: change the group by hand` [S: the inherited view]); `mgmt-acl` when the filter is applied on lo0 and `--from <address>` was given and is not inside a `permit-mgmt` source of the rendered filter; `netconf` or `breakglass` named in `--section` (a usage error). **Warnings** (in the header, and the block still carries the section): `mgmt-acl` with the filter on lo0 and no `--from` (`check that the address you are logged in from is inside a permit-mgmt source before you paste; --from <address> makes tacctl check`); a pull older than `stale-days`; the pull's login could not see secrets (`?` statements are left alone); an engineer's class lacks a bit a section needs (`roles` needs `admin-control`, `snmp` needs `snmp-control`, the server `secret` needs `secret-control` [A: the Junos reference; EN-CLASS has none of the three, V: `engineerBits`]; **[L1]** confirms with private loads as a `gotest*` engineer): `your class EN-CLASS cannot commit roles, snmp: paste those as a superuser` (a note, not a refusal: the person may paste under another account). ## 3. The block, as the person sees it (Junos)

Values are documentation addresses; the device is the lab fixture's shape (a server secret already present, an extra accounting event, a community with `clients` entries where tacctl renders a client list).

```
$ tacctl device config plan sw-lab-1
# tacctl device config plan: sw-lab-1 (scope lab, juniper, TACACS+)
# Based on the pull of 2026-10-10 14:02 by alice over netconf (18 minutes ago; the
# login could see secrets) and the tacctl rendering of 2026-10-10 14:20 (tacctl 0.2.5).
# Planned: aaa (1 statement), snmp (5 statements). No change: roles, mgmt-acl.
# Not planned: netconf, breakglass (the walkthrough's Steps 6 and 7). Kept: 2 lines.
# Secrets: 1 present on the device, not changed (--secrets re-pushes it).
# THIS BLOCK HOLDS THE SNMP COMMUNITY OF SCOPE lab: do not leave it in a scrollback or a file.
#
# 1. Before you paste, in operational mode on sw-lab-1 (and nowhere else):
#      show version | match Hostname               this is the device the block is for
#      show system commit | match "^0"              who committed last, and when
#      show system users                            is anyone else in configure mode?
#      show configuration | compare rollback 0      must print nothing (no uncommitted work)
#    Keep a second terminal logged in to sw-lab-1 as yourself until the end.
#
# 2. Paste, in configuration mode (the first line opens a private candidate):
configure private
# aaa: the accounting events tacctl renders (login and change-log only)
delete system accounting events interactive-commands
# snmp: the client list and the read-only community tacctl renders for scope lab
set snmp client-list TACCTL-SNMP 192.0.2.10/32
set snmp client-list TACCTL-SNMP 198.51.100.0/24
set snmp client-list TACCTL-SNMP 0.0.0.0/0 restrict
set snmp community example-community client-list-name TACCTL-SNMP
delete snmp community example-community clients
# kept on the device (not rendered by tacctl, left as they are):
#   set system tacplus-server 192.0.2.10 source-address 192.0.2.77
#   set snmp name sw-lab-1.example.net
show | compare
commit check
commit confirmed 5 comment "tacctl plan sw-lab-1 2026-10-10T14:20Z by alice"
#
# 3. While the 5-minute window runs:
#    from the tacctl server (a fresh login as you through TACACS+, then the comparison):
#      tacctl device config pull sw-lab-1 --diff      aaa and snmp must read ok; kept lines show as +
#    from the second terminal:
#      show cli authorization
#      show configuration system accounting
#      show configuration snmp
#
# 4. If both pass, back in this session, before the window ends:
commit
exit
#
# To back out:
#   before 'commit confirmed':   rollback 0, then exit
#   during the window:           rollback 1, then commit   (or let the window expire)
#   after the confirming commit: rollback 1, then commit   (only while 'show system commit'
#                                shows nobody committed after you)
# Do not: 'commit' without 'confirmed'; 'load override'; leave a 'configure exclusive' session
# open; paste this into any other device.
```

With `--plain` the same device prints the six statement lines and nothing else. An engineer whose group's class is EN-CLASS sees one more header line: `# Your class EN-CLASS cannot commit snmp (snmp-control): paste that part as a superuser, or hand the block over.`

## 4. What the planner emits, per section (Junos)

| Section | Emitted | Owned objects (extras inside them get `delete`) | Kept (listed as comments) |

## 10. Risks

1. **The block deletes something it should not.** Mitigation: the ownership tables are data with a test per row; every `delete` is shown with its section's reason; the property test proves convergence on every fixture; Opus reviews the planner; the lab check loads real blocks without committing.
2. **A person pastes into the wrong device.** Mitigation: the header and the first pre-check name the device; one block per device, never a combined one; `--out-dir` names files by device.
3. **The wrapper's commit lines are written from the reference** (L3 not run). Mitigation: the 0.2.4 spike confirmed CLI `commit confirmed` and its expiry [S: (d)]; the comment syntax is the reference's; the release notes say what was not lab-run; a go-ahead can close it before the release.
4. **The engineer's class note is wrong** (L1). Mitigation: a note, not a refusal; L1 runs first.
5. **Size.** The Cisco emitter, `--json` and `--out-dir` are cut first; the block, `--plain`, `--secrets`/`--no-secrets`, `--out`, the property test and `rollback 0.2.4` are not cuttable.
6. **Shared files** (`device_config.go`, `tier.go`, docs, goldens): serialised in the execution plan.

## 11. Open questions for the user (recommended answers)

1. **The verb is `device config plan`**, beside `show` (the fresh-device walkthrough) and `diff` (the report): recommended yes.
2. **Lines pasted into configuration mode, not `load set terminal`**; the plain file is the `load set <file>` form: recommended yes.
3. **`configure private` as the first pasted line**, `exclusive` named as the alternative: recommended yes.
4. **The verification while the window runs is `tacctl device config pull <name> --diff` from the server plus a second-terminal login**: recommended yes.
5. **A missing secret is pasted by value; present ones are not printed unless `--secrets`; `--no-secrets` prints `<SECRET>`**: recommended yes.
6. **`--from <address>` is optional: with it the filter check refuses `mgmt-acl` when the address is not permitted; without it a warning**: recommended yes.
7. **Cisco blocks are emitted, marked not lab-tested, with `write memory` as the person's step and the revert timer as an unverified note**: recommended yes (cut first if the release grows).
8. **L3 (the `commit confirmed … comment` syntax and `rollback 1` + `commit` as the cancel) needs a commit on the lab switch**: recommended to keep it [A] for the release and ask for a go-ahead only if the user wants it closed before 0.2.5 ships.
