# 0.2.8 lab results: IOS blocks, restore point, device facts

Three IOS lab routers (IOS 12.4(15)SW on a 7200 emulator, IOSv 15.6(2)T and
IOS-XE 16.7.1 on a CSR1000v) and one Junos switch (25.4R1-S2.3), read through
tacctl's own pull and plan as a TACACS+ login. Changes to a router were
pasted from the plan and taken back with `configure replace <file> force`.

## IOS system and snmp blocks

A device block of each kind (banner, `ip domain name`, `ip domain list`,
`clock timezone`, `ip name-server` with two addresses, two `ntp server`
lines, one with `prefer` and one with `version 3`; a community, a trap host,
`enable traps config`, `snmp-server trap-source`) was set, planned, pasted and
pulled again.

| Line | 12.4(15)SW | 15.6(2)T | IOS-XE 16.7.1 |
|---|---|---|---|
| banner, domain name and list, name servers, snmp lines | as typed | as typed | as typed |
| `clock timezone UTC 0` | not printed | not printed | not printed |
| `ntp server H version 3` | stored as `ntp server H` | as typed | as typed |
| `ip name-server A B` | one line per address | one line per address | one line, both addresses |
| `snmp-server trap-source` | not tried | as typed | as typed |

Findings and what was done about them:

- `clock timezone UTC 0 0` is the default zone and no release prints it, so
  the section read `differs` for good. The compare treats the rendered line
  as present on a device that has no `clock timezone` statement.
- 12.4 stores the default NTP version 3 without the option. A device in the
  IOS 12.x syntax is rendered and compared without `version 3`; 15.x prints
  the option and a bare line means version 4, so the rule is keyed on the
  syntax (`Request.Legacy`), not on the release. Other options and versions
  stay.
- The system block's NTP key lines were not run. The plan's report names them
  and nothing else of the two blocks as not checked on a device.

## VRF forms and the informs kind

Typed and read back on 15.6(2)T and 16.7.1 (a `vrf definition` with an ipv4
address family):

| Typed | Stored |
|---|---|
| `ntp server vrf V H prefer version 3` | as typed |
| `ip name-server vrf V A B` | 15.6: one line per address; 16.7: as typed |
| `ip domain name vrf V name` | as typed |
| `ip domain list vrf V name` | as typed |
| `snmp-server host H vrf V version 2c C` | as typed |
| `snmp-server host H informs version 2c C` | as typed |
| `snmp-server host H version 2c C udp-port 1162 config` | as typed, two blanks before `config` |

Removal: `no ntp server vrf V H`, `no ip name-server vrf V A B`, `no ip
domain name vrf V`, `no ip domain list vrf V N` and `no snmp-server host H vrf
V C` took their line away. Removing the VRF left an `ip dns view vrf V
default` line behind.

## Trap host identity

On 15.6(2)T and 16.7.1, for one address and community IOS keeps one entry per
kind (traps, informs) and per udp-port (162 by default): `snmp-server host H
version 2c C`, `snmp-server host H informs version 2c C` and `snmp-server host
H version 2c C udp-port 1162` are three entries. The version and the
notification types are attributes of an entry, replaced in place by typing the
line again: `snmp-server host H version 2c C` followed by `... C config` left
one entry with `config`, and `version 1 C` replaced the version of the plain
entry. tacctl's identity is therefore (address, vrf, kind, udp-port,
community), with traps and 162 as the defaults.

Removal of a host: `no snmp-server host H version 2c C udp-port 1162`, with no
types, took away the entry that had `config`; `no snmp-server host H informs
version 2c C` took away an informs entry; `no snmp-server host H C` took away
neither. The back-out of a host is `no` and its line up to and including
`udp-port N`, the types left out.

`snmp-server host H informs C` (no version) is refused with `%Informs not
supported in SNMPv1`, so a block's informs host states `version 2c`.

A host line does not create its community: after typing one with a community
the router lacked, `no snmp-server community C` answered `Cannot find
community`. Nothing in the plan warns about or removes a community for a host.

## Restore point

On all three routers, with no `archive` configured: `copy running-config
<fs>tacctl-...cfg` wrote the file, the pasted region converged on the next
pull, and `configure replace <file> force` returned the access list to its
first state. On 12.4 a replace of a system block aborted after five passes at
`no ntp server H prefer`, which that release rejects (its own `no ntp server
H` works); the lines had to be removed by hand. The back-out's own undo of an
NTP server is `no ntp server H`.

## Device facts

`device config pull` recorded the release, model and serial of all four
(15.6(2)T / IOSv, 16.7.1 / CSR1000V, 12.4(15)SW / CISCO7206VXR, 25.4R1-S2.3 /
EX4300-48MP) and `device show` and `device config list` showed them.

## Test accounts

The tacctl test account `gotestsu` logged in through the routers' TACACS+
login; a router's local `admin` is refused while the server answers, as the
standard's `aaa authentication login default group TACACS-GROUP local` says.
