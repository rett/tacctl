## 0. Summary

- **Goal:** make a device run the sections tacctl renders for it. `tacctl device config apply` logs in as the invoking user, reads what the device runs, computes the statements that take it from there to the rendering, loads them into a private candidate, validates, shows the change for review, commits under an automatic rollback, proves the device is still reachable through the AAA path with a fresh login, and only then confirms. `tacctl device config rollback` undoes the last apply the same way. Junos first and in depth; Cisco is refused until a lab router settles its mechanics; WTI is 0.2.6.
- **Shape:** one transaction driver over a vendor transport interface that carries `Confirms()` (D77); the Junos transport is NETCONF in a private edit session (D78); a planner that turns the diff of 0.2.4 into `set`/`delete`/`insert` lines under an ownership rule that never touches what tacctl did not render except inside objects it owns (D79, D80); lock-out guards that no flag skips (D81); a confirmed commit held open on one session through the verification to the confirming commit (D82); a two-phase run, plan then apply, where `--dry-run` is the plan phase and the plan already loads and checks the candidate on the device (D83); a canary first, `--max-failures 1` by default (D84); records and `device config rollback` from the device's own commit history (D85, D86); engineers for their own scopes, with a pre-flight of what their class may write (D87); the same batch runner, cache, records and transports as 0.2.4.
- **Order:** the lab spike (WP12.0) runs first and in parallel with the offline packages; every offline package has a fallback for each [L] item (§9). The lab switch is live-testable by the coordinator under the 0.2.4 safety posture; there is no lab router.
- **Enabling NETCONF** (D93): the one statement apply needs and cannot write through its own transport, `set system services netconf ssh`, is written by a narrow superuser verb over the ssh command line, under a confirmed commit proved by a NETCONF hello as the user; nothing else of `netconf` is ever written.
- **Size:** 12 packages, ≈ 13-16 sessions, ≈ 7,500-9,500 lines (D93 adds about one session). `device config rollback` is cut first if the release grows (§11); the record keeps what a later rollback needs either way.

## 1. Goals and non-goals

### Goals

1. **`device config apply`** (D77-D84): one or many Junos devices, the sections `aaa`, `roles`, `mgmt-acl` and `snmp` (D79), reviewed, committed under an automatic rollback, verified, confirmed; one line per device and a summary, as the pull.
2. **`--dry-run`** (D83): the plan phase alone: the change per device, validated on the device in a discarded private candidate.
3. **Rollback on the device** (D82): a failed verification, a lost session, an interrupt or a dead tacctl leaves the device as it was.
4. **`device config rollback`** (D86): the last apply undone, section by section, from the device's commit history, with the same review and the same protection.
5. **Records** (D85): what was applied, when, by whom, under which change identifier, with what result, and what a rollback needs.
6. **Tiers** (D87): superusers everywhere; engineers for the devices of their own scopes with their own login; a pre-flight of what the login's class may write.
7. **The seam for Cisco** (D77, §5): the transport interface and the list of what a lab router must settle; nothing is applied to a Cisco device in 0.2.5.
8. **`tacctl rollback 0.2.4`** (D91) for the new keys and the sudoers text.
9. **`device config enable-netconf`** (D93): the single statement that makes a Junos device reachable by apply, written over the command line under a confirmed commit, superuser only.

### Non-goals (0.2.5)

- Cisco apply (D77: refused with the reason; the unknowns are listed in §5.3). IOS-XE over NETCONF stays conditional on `netconf-yang` (backlog §0).
- WTI (0.2.6). Per-device source address (backlog §0b, parked): mentioned only where apply meets a configured one (D79: left alone).
- Unattended or scheduled apply (0.2.7: a service account). Apply needs a person and their password, as the pull does.
- Writing `breakglass`, the lo0 application of the filter, `system root-authentication`, `system services ssh`, `groups` or `apply-groups` (D79, D81): never, whatever flag is given. Of `netconf`, apply writes nothing; the one statement `set system services netconf ssh` is D93's verb and nothing else of the hierarchy (no `connection-limit`, no `rate-limit`, no port) is ever written.
- Pruning foreign statements in a managed hierarchy (another server, another community, the operator's own classes): D79 keeps them; a `--prune` is a backlog idea, not designed.
- Apply over the Junos command line (D77): NETCONF only; a Junos device without NETCONF is refused and told to run `device config enable-netconf` (D93).
- A per-device commit comment, commit scripts, `commit synchronize` options (D82: the device's own `system commit synchronize` setting governs a dual-RE; not tested).
- Comparing secrets by value, storing any secret value, a pre-apply copy of the sections (D85: the device's history is the record and a copy could restore no secret).

## 3. The apply transaction

### 3.1 State machine (one device, Phase B; Phase A stops after CHECK and discards)

```
DIAL ──auth/key/unreachable──▶ FAILED (record: result of the attempt; device untouched)
  │
HELLO ──no candidate/confirmed-commit cap──▶ FAILED "cannot confirm" (Confirms() false)
  │
PREFLIGHT  show cli authorization → class, bits; sections → writable / skipped   (D87)
  │        show system commit; compare rollback 0 (shared)                       (D88)
READ       get-configuration inherit=inherit format=set, and the plain view;
  │        extract (0.2.4); compare (0.2.4); the pull part of the record is refreshed
PLAN       delta = set / delete / insert (D79, D80); guards (D81); inherited? → FAILED
  │        empty delta ──▶ NO-CHANGE (no candidate; exit 0 for the device)
  │        Phase B: delta ≠ reviewed and not --force ──▶ FAILED "changed since the review"
OPEN       open-configuration private   (warning: exclusive active ──▶ FAILED "locked by")
  │
LOAD       load-configuration action=set; any error-severity rpc-error ──▶ DISCARD → FAILED "load: <bad-element> <msg>"
  │
VERIFY-C   get-configuration database=candidate … format=set; extract; compare with the target:
  │        any '-' or '!' or a '+' outside kept ──▶ DISCARD → FAILED "candidate does not match the target"
CHECK      commit-configuration check ──error──▶ DISCARD → FAILED "check: <path> <msg>"; lock-denied ──▶ FAILED "locked by"
  │        get-configuration compare=rollback 0 (the brace diff: line count only)
  │        ── Phase A ends here: close-configuration (discard) → the review ──
COMMIT-C   commit confirmed N, log "tacctl apply <id> by <user>"  ──error──▶ DISCARD → FAILED
  │        (from here the device is on the new configuration under a rollback timer)
VERIFY-L   fresh ssh+NETCONF login as the user → read → compare applied sections;
  │        snmp "not worse" read (D82)
  │        any failure, timeout, or the original session gone ──▶ ROLLED-BACK:
  │          close the original session without confirming (the device rolls back at once),
  │          re-dial and read → record "rolled-back"; no read possible → "unknown"
CONFIRM    <commit/> on the original session ──error (retry once)──▶ close → ROLLED-BACK
  │
RECORD     read on the fresh session; record applied (id, sections, counts, commit refs); close both
```

### 3.2 What the device and the record look like after each exit

| Exit | Device | Record (`applied`) | Line |
|---|---|---|---|
| FAILED before OPEN | untouched; no candidate | `result=failed reason=…` (the pull part refreshed when READ ran) | `failed: <reason>` |
| FAILED at LOAD / VERIFY-C / CHECK | untouched; the private candidate discarded by `close-configuration` | `failed` with the load or check message | `failed: load: …` |
| NO-CHANGE | untouched | unchanged (the previous apply stands); the pull part refreshed | `no change` |
| Phase A end (`--dry-run` or the review) | untouched; candidate discarded | `phase=plan` not recorded in `applied`; the pull part refreshed | the review |
| ROLLED-BACK | as before the apply (the device's own rollback on session close; the timer is the backstop) | `rolled-back reason=…` | `rolled back: verification failed (…)` |
| UNKNOWN | rolled back by the device (session closed) but not re-read | `unknown` | `unknown: check the device (the confirm timeout rolls it back)` |
| APPLIED | the target; two history entries carry the id | `applied`, counts, `commit`, `pre` | `applied (aaa,snmp: 7 set, 2 delete)` |
| Interrupted (first Ctrl-C) | a running device finishes its transaction, through CONFIRM or ROLLED-BACK; nothing new starts | as the exit it reached | `interrupted: N not started` |
| Interrupted (second Ctrl-C) or SIGTERM | the contexts are cancelled: a session closes wherever it is; before COMMIT-C the private candidate is discarded by the close, after it the device rolls back as the session closes | `interrupted` (before COMMIT-C) or `rolled-back reason=interrupted` (after, re-read when possible) | `interrupted` |
| tacctl killed or the host dies | the same as the second interrupt: the TCP close is the rollback; a host that vanishes leaves the confirm timeout to do it | the record keeps whatever was last written (the plan or nothing) | — |

A device is never left with a confirmed commit pending that something else must confirm: the only thing that can confirm is the session that committed, and that session lives in the job's goroutine; when the job ends by any path other than CONFIRM, the session is closed.

### 5.3 The Cisco seam and its unknowns

The interface is written so that an IOS/IOS-XE transport can be added without touching the driver: `Confirms()` would be true for a CLI transport only when `archive` is configured and `configure terminal revert timer` is accepted (the 0.2.4 spike's assumptions [V: `0.2.4-spike.md` IOS-XE]); `Open` would be `configure terminal revert timer N`, `Load` the lines typed one by one (live, no candidate: the ordering and the lock-out guards are then the planner's), `Check` nothing (IOS has no check), `CommitConfirmed` a no-op (the timer is already running), `Confirm` `configure confirm` then `write memory` (a `Persist` step the Junos transport does not need), `Discard` `configure revert now`. **Unknowns to settle on a lab router before any of it is designed:** (1) whether `configure terminal revert timer` and `configure confirm` exist on the IOS releases in use and need `archive` with a `path`; (2) what happens to the timer when the ssh session drops (the reference says it runs to expiry: a lost session reverts late, not at once, the opposite of Junos); (3) whether the revert can be confirmed from another session; (4) how `aaa authorization config-commands` and per-level authorization treat the lines an engineer types through apply; (5) how an ACL bound to `line vty` can be replaced without a window in which the vty is closed (a temporary ACL and a swap?); (6) whether `show archive config differences` is usable as the diff and what it prints for secrets; (7) `netconf-yang` on IOS-XE: whether its NETCONF offers `candidate` and `confirmed-commit`, which would make the Junos driver reusable; (8) whether `write memory` after `configure confirm` is needed for the change to survive a reload; (9) the exact error texts (`% Invalid input`, `% Ambiguous command`) the line-by-line load must detect. Until then every Cisco device is refused by `Confirms()` (D77).

## 6. Data model

- **The record** (D85): `applied` as listed; `Records.Version` 1. The sections file is unchanged (the post-commit read rewrites it as a pull does).
- **Settings** (D91): `device.config.confirm_timeout`, `device.config.apply_timeout` in `tacctl.yaml`, written only when set.

## 7. Concurrency and interruption

- One pool (D67) for Phase A; Phase B runs the canary alone, then the pool (D84). `Concurrency = min(flag, device.config.max_concurrency, N)`; the per-device budget is `apply_timeout`.
- The password is resolved once, before Phase A (D70); the fresh login of D82 uses the same string; a refusal there is a verification failure, not a rejection (D82); `Accepted()` fires on the first successful dial as in the pull.
- The first interrupt stops starting devices and lets running transactions finish through CONFIRM or ROLLED-BACK (a transaction is never cut by the first Ctrl-C: cutting it would be a rollback anyway, but a finished one is a known state); the second cancels the contexts (§3.2). SIGTERM and SIGHUP cancel at once, as in the pull.
- Nothing is shared between workers but the password source, the records store (locked) and the read-only `Data` per scope; the review groups deltas after Phase A ends, on the main goroutine.
- Between the phases no session is held (D83); the NETCONF idle timeout [L8] is therefore irrelevant to the review's length.

## 11. Risks

1. **Apply deletes something it should not.** Mitigation: the ownership tables are data with a test per row; the review shows every `delete`; the read-back compares against the target; Opus reviews the planner and the driver for what can be deleted; the lab acceptance compares byte for byte after a rollback.
2. **A pending confirmed commit outlives tacctl.** Mitigation: the session-close rollback is the device's [S]; the confirm timeout is the backstop; the state table §3.2 is tested exit by exit on the fake; L3 confirms the TCP-drop case.
3. **The engineer class cannot write what the roadmap promised.** Mitigation: L1 first; the pre-flight reports skips instead of failing; open question 3 for the user.
4. **Junos surprises in the RPC forms** (L5, L6, L7). Mitigation: each has an offline fallback; the spike runs first.
5. **Size.** `device config rollback` (WP12.5b) is cut first; then the review's grouping of identical deltas; then the SNMP "not worse" check. The canary, `--dry-run`, the verification, the records and `enable-netconf` (the user's addition) are not cuttable.
8. **The command-line enable path parses text** (D93): no exit status, no structured error. Mitigation: one statement, success phrases required, fail closed on anything else, a hello as the proof, `rollback 1` + `commit` to cancel, the fake's texts from L12's captures, Opus reviews the parser.
6. **Shared files** (`device.go`, `device_config.go`, `tier.go`, docs, goldens): serialised in the execution plan.
7. **The review in a 60-device batch is long.** Mitigation: identical deltas are grouped; `--dry-run --json` for tooling; `--section` to narrow.
