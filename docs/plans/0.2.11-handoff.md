## Scope of 0.2.11 (user, 2026-10-15): hardening and discoverability

No state-format change and no new device write path. Each item is its own
gated unit with its CHANGELOG item, man page and docs page.

1. **`group preset list`** and **a `group list` hint when the engineer tier
   has no group.** To settle first: what `preset list` shows that
   `group preset roles --dry-run` does not, and when the hint prints (not
   in `--json`, not once a group has the tier).
2. **`config validate` warns about `privileges.<group>: []` on a built-in
   group** (an empty list hides the shipped default; `group privilege reset`
   removes it). Backlog section 0b.
3. **`StoreApply` rolls back only what the failed command wrote.** Today a
   failed writer or render restores whole copies of `store.yaml` and
   `tacctl.yaml`, which also undoes another command's change made in
   between. To settle first, with a design note and a review before code:
   restore the keys the command wrote, or hold one lock from the first copy
   to the restart. The restart staying outside the transaction is not part
   of this item. Backlog section 0b.
4. **A release-reproducibility check in CI** (backlog section 2): rebuild the
   assets from the tag and compare with the published `SHA256SUMS`. There is
   no workflow in the repository yet; adding one is the first CI.
5. **NETCONF runs not yet made on a lab switch** (so a later release can
   decide on `auto` as the default): a large batch against one switch (the
   connection and rate limits), another editor's commit between the gate and
   the lock. A second Junos release needs a device the lab does not have.
   These touch the lab switch: ask the user first, as in 0.2.10.

Not in 0.2.11: device accounts and break-glass rotation (decide first:
store a hash, or generate and show once), unattended drift detection,
`device config rollback` (D86), IOS and WTI apply, ASA, and everything in
0.3.0 (the built-in `engineer` group among it).

## Working rules

- Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides
  important design questions. Subagents never commit; the coordinator reviews,
  merges, renumbers CHANGELOG items and commits.
- Commit when appropriate (a coherent unit of work that has passed its
  gates); ask before pushing, and push only the branch being worked on;
  merges into `develop` and `master`, tags and releases only when the user
  says so. No Claude attribution in commit messages.
- No private names (hosts, addresses, users, home paths, domains) and no
  description of any installation's state or deployment in repo files or
  commit messages: use roles ("the dev server", "the lab switch") and
  `example.*`, `192.0.2.x`.
- Never act against the production host and never connect to a production
  device: prepare the files and let the user apply them.
- Every user-visible change gets a numbered CHANGELOG item and updates
  `man/tacctl.1` and the matching `docs/` page in the same change.
- Gates: build, gofmt, `go vet`, `make lint`, Go tests (`internal/cli` needs
  `setsid -w ... < /dev/null`, a scratch `GOCACHE`), bats as the invoking
  user, the diff corpus against the previous release, the container matrix,
  `groff -k -ww`. Tests sandbox host paths.
