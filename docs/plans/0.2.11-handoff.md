## State

(`scope netconf`, `device netconf`) and apply over NETCONF as an opt-in

## Scope of 0.2.11 (user, 2026-10-15): hardening and discoverability

No state-format change and no new device write path. Each item is its own
gated unit with its CHANGELOG item, man page and docs page.

1. **`group preset roles` shows what each setting changes** (done,
   CHANGELOG item 1): the value now and the preset's, the rules and deny-set
   patterns removed and added, under each step that is not unchanged.
2. **`device list` and `device show` refresh the seen cache** (done,
   CHANGELOG item 2): logs only, at most five seconds, only for a caller who
   may scan, never the first scan or the catch-up of an old cache, silent on
   any failure.
3. **`group list` hint** when no group has the engineer tier, and **`config
   validate` warning** for an empty `privileges.<group>` on a built-in group
   (done, CHANGELOG items 3 and 4); the help text of the apply-transport
   default and the completion kinds (items 5 and 6).
4. **One apply lock for the commands that put whole files back** (done,
   CHANGELOG item 9; design in `0.2.11-plan.md`, D152-D158): a failed
   writer or render used to restore whole copies of `store.yaml` and
   `tacctl.yaml`, which also undid another command's change made in
   between. `<state>/.store-apply.lock` (reentrant per process, polled so
   Ctrl-C ends the wait) is held by `StoreApply`, `ApplyForced` and
   `ConfigRender` through their restarts, by every `tacctl.yaml` write, and
   by the outer transactions (`config listen|loglevel|metrics`, the RADIUS
   listener changes, `backend enable|disable`, `store import|rollback`,
   `backup restore`, `upgrade` after its self-update). A hand-edited file
   is saved as `<file>.overwritten-<stamp>` before a rollback restores it.
   The restart staying outside the transaction is not part of this item.
   Backlog section 0b.
5. **A release-reproducibility check in CI** (done, CHANGELOG item 7):
   `tests/tools/release-reproduce.sh`, `make release-reproduce`, the
   `release-reproducible` workflow, and the stamp and metadata checks of
   `release-verify` and `release-assets`. The first run of the workflow is
   0.2.11's own release.
6. **NETCONF runs on a lab switch** (done, `0.2.11-lab.md`, CHANGELOG item
   8): repeated applies and simultaneous sessions are not bound by the
   connection and rate limits (they bound port 830); a commit during the
   review is tolerated and one that changes the delta is refused. Not run:
   another Junos release.

Not in 0.2.11: device accounts and break-glass rotation (decide first:
store a hash, or generate and show once), unattended drift detection,
`device config rollback` (D86), IOS and WTI apply, ASA, and everything in
0.3.0 (the built-in `engineer` group among it).

## Working rules

- Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides
  important design questions. Subagents never commit; the coordinator reviews,
  merges, renumbers CHANGELOG items and commits.
- Commit when appropriate (a coherent unit of work that has passed its
  gates); ask before pushing, and push only the branch being worked on;
  merges into `develop` and `master`, tags and releases only when the user
  says so. No Claude attribution in commit messages.
- No private names (hosts, addresses, users, home paths, domains) and no
  description of any installation's state or deployment in repo files or
  commit messages: use roles ("the dev server", "the lab switch") and
  `example.*`, `192.0.2.x`.
- Never act against the production host and never connect to a production
  device: prepare the files and let the user apply them.
- Every user-visible change gets a numbered CHANGELOG item and updates
  `man/tacctl.1` and the matching `docs/` page in the same change.
- Gates: build, gofmt, `go vet`, `make lint`, Go tests (`internal/cli` needs
  `setsid -w ... < /dev/null`, a scratch `GOCACHE`), bats as the invoking
  user, the diff corpus against the previous release, the container matrix,
  `groff -k -ww`. Tests sandbox host paths.
