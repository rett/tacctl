# tacctl 0.2.12 plan (2026-10-15)

Read `0.2.12-handoff.md` (state, working rules) first. Decisions continue
the numbering of `0.2.11-plan.md` (D152-D158).

## 1. Scope

A small-follow-ups release: the items the 0.2.11 reviews filed as "later",
each its own gated unit with its CHANGELOG item, man page and docs page
where it is visible to a user. No state-format change, no new device write
path, no new credential.

| WP | Item | User-visible |
|---|---|---|
| 12.1 | `config get` completes every key of the schema, not a fixed list | yes (completion) |
| 12.2 | `config validate` warns for keys that name a group or scope the store does not have | yes |
| 12.3 | The tier notes come from a field on the rule, not a second list | no (the man TIERS block must not change) |
| 12.4 | A re-run of `tacctl install` takes the apply lock | yes (known limit of 0.2.11 removed) |
| 12.5 | A Go test job in CI | no |
| 12.6 | The `internal/cli` run is measured and its slowest tests cut or split | no |

Order: 12.1, 12.2, 12.3 (code the same files, small), 12.4, then 12.6 before
12.5 (a CI job should not start at twenty minutes).

## 2. Direction (decided 2026-10-15)

Every tacctl operation is started by a person at the time it runs. tacctl
holds no credential for a device and runs no operation on a schedule, and
none is planned. The roadmap items that needed one are dropped: device
accounts and break-glass rotation, a service account, unattended drift
detection, the break-glass users block with a stored hash, and a timer that
releases a hold. A person who wants a periodic report runs `device config
diff --pull` themselves, with their own password.

One thing already built is in tension with this and is not changed here:
D159 below.

## 3. Decisions

| # | Decision | Status |
|---|---|---|
| D159 | The session-start background scan of 0.2.11 (`device scan --if-stale --quiet`, detached, from an interactive console or shell, at most every five minutes) starts without a command being typed. Options: keep it; make it opt-in (`config devices session-scan on`, default off) and let the `device list` footer reminder carry the staleness; remove it. It reads no credential and writes only the seen cache, and the host-key rescan stays at 24 hours. | open, for the maintainer |
| D160 | 12.1: the completion words are the schema's keys (`Schema.Keys()`, wildcard families expanded from the store where the family is keyed by scope, group or backend), not the constant `configPaths`. A secret key is completed like any other and its value is never printed by completion. | proposed |
| D161 | 12.2: a warning, never an error, for each of `privileges.<g>`, `commands.<g>`, `tier.<g>`, `junos.<g>.*` naming a group the store lacks and each of `snmp_scope.<s>.*`, `breakglass_scope.<s>.*`, `blocks.<s>.*`, `cisco.source_interface.<s>`, `netconf.<s>` naming a missing scope; the line names the key and says `config unset <key>` removes it. Built-in group names and `default` are never orphans. | proposed |
| D162 | 12.3: a `Note` field on the sudo/tier rule row; the TIERS man block and the `help` notes are generated from it; the existing test that fails for a narrower row without a note stays. | proposed |
| D163 | 12.4: `tacctl install` takes the apply lock around the writes of `tacctl.yaml` and `store.yaml` and the restarts, as `upgrade` does after its exec; it waits and says so as the other commands do. | proposed; check first which writes a re-run really makes |
| D164 | 12.5: one workflow job, `make test-go` with `fetch-depth: 0` (the two tests that need the 0.2.2 tag run, not skip), run as a user with no tty (`setsid`, stdin from `/dev/null`); the bats suite and the container matrix stay on the maintainer's machines. | proposed |
| D165 | 12.6: `go test -json` per-test times for `./internal/cli`; tests over ten seconds are listed in this note; a test is cut only where it repeats another's coverage, never skipped. Target: under ten minutes, no test removed for speed alone. | proposed |

## 4. Gates

As the handoff: build, gofmt, `go vet`, `make lint`, Go tests, bats as the
invoking user, the diff corpus against 0.2.11, the container matrix,
`groff -k -ww`. WP 12.1 and 12.3 add tests that compare against the schema
and the tier table so a new key or verb cannot go without a completion or a
note.

## 5. Not in 0.2.12

`device config rollback` (D86, `apply-deferred.md`), NETCONF on another
Junos release (run when a second release is on the lab bench), IOS and WTI
apply, ASA, and the 0.3.0 format work.
