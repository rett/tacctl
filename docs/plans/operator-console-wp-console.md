# tacctl 0.2.1: login console work packages (amendment, 2026-10-04)

> Amends `docs/plans/operator-console-wp.md` for the user decisions of 2026-10-04: the console ships in 0.2.1, is on by default for every tier, and gains a `system-shell` builtin (superusers only by default). Where this document and the base plan disagree, this one wins. Written by Fable against `feature/0.2.1` at `7cca787`.

> **Open questions decided (user, 2026-10-04):** (1) the builtin is `system-shell`; (2) superuser lines in `tacctl shell` and the console run plain `sudo` (readonly/operator keep `-n`); (3) the `tac-console` drop-in sets `PubkeyAuthentication no`; (4) the console refuses `tacctl ssh` to an unpinned entry; (5) `console tiers|user` writes print the `host sync <local>` command and do not sync; (6) the console case joins the hosts container matrix if the server image runs sshd, else WP7.4 is the only sshd proof, recorded in the gate.

## Open questions (each with a recommendation)

1. **Name of the builtin.** Recommend **`system-shell`**: `bash` would be wrong on a site whose `system_shell` is another shell and reads like a program that works for everyone; `system-shell` completes with Tab, shows "(administrators only unless enabled)" in `help`, and cannot be confused with a tacctl verb.
2. **Superuser lines without `-n`** (§5.0 correction 2). Recommend **yes, in WP7.1, for `tacctl shell` and the console alike**; the alternative (keep `-n`) leaves console superusers unable to run any write verb except through `system-shell`.
3. **`PubkeyAuthentication no` in the `tac-console` drop-in.** Recommend **yes**: console users authenticate through TACACS+ by design, and a key login bypasses it (pam_tacplus's account phase cannot run for key logins, design §6.5); a stray `authorized_keys` left by an administrator would otherwise be a password-free login. Alternative: leave sshd's default and document.
4. **Unpinned entries in the console: refuse (design §6.5) or warn and use the user's own `known_hosts` (as `tacctl ssh` does from bash).** Recommend **refuse**, as designed: enrolled hosts are pinned at enrolment and devices at `device add` unless an administrator chose otherwise, and the refusal names `device hostkey <name> accept`.
5. **Should `console tiers|user` writes run `host sync <local>` themselves?** Recommend **no** (print the command; sync stays the one explicit account-changing step, as today); a `--apply` flag is a later convenience if asked.
6. **Console case in the hosts container matrix** depends on the server image running sshd ([A] 11). Recommend **add it if the image has sshd, else accept WP7.4 as the only sshd proof** and say so in the gate record.
