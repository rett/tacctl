## 2. Decisions

| # | Decision | Status |
|---|---|---|
| D175 | `device address` on a held device moves the hold. The new address passes the checks a new hold passes (not loopback, not a listener of the server, not an enrolled host's address, not held by another record, covered by a scope); one line names both addresses and asks to confirm (`-y` skips it); one write of the registry and the record, one render, one restart. A refused address refuses the whole change ("Nothing was changed."). A failed restart reports `NOT restarted` and exits 1, as `breakglass hold` does. Releasing first is the wrong answer in the case this is for: it re-answers the old address. | decided |
| D176 | A hold on an enrolled Linux host is built (the earlier proposal to close it was not taken). The mechanism is the device hold's: `breakglass_hold.<name>` in `tacctl.yaml`, the address carved out of every scope by the renderers. The refusal "a host is never held" goes; the checks that stay are the server's own address, loopback and the machine tacctl runs on. Open design points are D179-D181. | decided |
| D177 | No request-sync queue. It is dropped from the backlog as not pursued; if it comes back, it starts from a fresh design. | decided |
| D178 | Action pins are bumped in one batch at the start of a release, only for releases two weeks old, with the `test` and `release-reproducible` workflows green on the pull request as the proof. First candidate: `upload-artifact` 7.0.2 (eligible 2026-10-21), so WP14.3 runs on or after that date. | decided |
| D179 | What a held host loses and keeps. A hold makes the server answer no login for the host's address; the host's local administrator and its console still work, which is the point. `host sync` and `host show --check` log in to the host as the caller and stop working while it is held: they refuse with the reason, as `device config pull` does for a held device. To be settled in the design: sudo through TACACS+ on the host (it stops with the logins). | to design |
| D180 | The shape of the record and the listings: the same record as a device's (since, by, reason, address); `breakglass list|status|hold|release` name hosts and devices alike; `host list|show` and `status` mark a held host; a host rename carries the record. A name that is both a host and a device is refused as ambiguous. | to design |
| D181 | The tier rule: holds are superuser-only, as for devices; an engineer sees the holds of the hosts of their own scopes. | to design |

## 3. Candidates weighed

**A hold that follows `device address` (WP14.1).** The refusal is a few
lines in `internal/cli/device.go` (the address change under a hold) and the
rename already carries a record (`holdCarry`, `internal/cli/breakglass.go`).
The difference from a rename is that the address is what the renderers carve
out of every scope, so the move needs the render and the restart of each
backend and the address checks of `holdCheck` on the new address. Touches
`device.go`, `breakglass.go` (a move beside the carry), `docs/cli/device.md`,
`docs/cli/breakglass.md`, the man page, about six tests. One session.

**A hold for an enrolled Linux host (WP14.2).** About two sessions. The
mechanism itself is unchanged (a hold is `breakglass_hold.<name>` in
`tacctl.yaml`; the address resolves through the registry), but the refusal
for hosts (`serverOwnAddress`, `holdCheck`), the orphan and JSON helpers
(`holdOrphan`, `holdJSONOf`), the way-in text by vendor, the `host`
listings and `status` all assume a device. A held host loses `host sync`
and `host show --check` and, by D179, sudo through TACACS+ for everyone but
the local administrator, so the lock-out reasoning of the device hold
applies to the host's own text.

**A request-sync queue.** Dropped (D177).

**Left as documented.** The restart that follows a render sits inside the
apply lock; a failed restart leaves the new files and the old daemon, and
the reports say so. Undoing the render would restart a daemon on the old
files and can fail again, which leaves less than now.

## 4. Gates

Each WP: build, gofmt, `go vet`, `make lint`, the Man tests and the
`internal/cli` run green before the next starts. WP14.1: a test for each
refusal of the new address; a test that a failed restart leaves the registry
and the record on the new address with exit 1 and `NOT restarted`; a bats
case that holds a device, changes its address and reads the rendered files;
the diff corpus shows only the address line and the hold comment moved; the
container matrix (`fresh`) observes the render. WP14.2: a held host is
refused by `host sync` and `host show --check` with the reason, listed in
`host list|show` and `status`, and carried by a rename; the container
matrix `hosts` runner observes the carve-out on a real client. WP14.3: both
workflows green on the pull request and the release notes name the new pins.
At release: bats, the diff corpus against 0.2.13, the container matrix, and
the `test` workflow on the release pull request.
