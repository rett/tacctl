# tacctl 0.2.14 plan (2026-10-17)

Read `0.2.14-handoff.md` (state, working rules) first. Decisions continue
the numbering of `0.2.13-plan.md` (D166-D174). Scope review: Fable,
2026-10-17.

## 1. Scope

A short release. No state-format change, no new device write path, no new
credential. Proposed; D175 and D178 decide it.

| WP | Item | User-visible |
|---|---|---|
| 14.1 | `device address` on a held device moves the hold instead of refusing | yes |
| 14.2 | The action pins are bumped once the newer release is two weeks old | no (CI) |
| 14.3 | Backlog hygiene: the lock bullet, the hold and queue bullets, the roadmap rows | no |

## 2. Decisions

| # | Decision | Status |
|---|---|---|
| D175 | `device address` on a held device moves the hold. The new address passes the checks a new hold passes (not loopback, not a listener of the server, not an enrolled host's address, not held by another record, covered by a scope); one line names both addresses and asks to confirm (`-y` skips it); one write of the registry and the record, one render, one restart. A refused address refuses the whole change ("Nothing was changed."). A failed restart reports `NOT restarted` and exits 1, as `breakglass hold` does. Releasing first is the wrong answer in the case this is for: it re-answers the old address. | proposed |
| D176 | A hold on an enrolled Linux host stays closed. A host keeps a local administrator with a usable password, `host sync` (ssh as the caller) would stop while it is held, and the mechanism would touch `holdCheck`, `holdOrphan`, `host list|show` and `status`. The backlog bullet is rewritten to say why; it reopens on a concrete case. | proposed |
| D177 | No request-sync queue in 0.2.14. If it is built later: the request lives in the per-host record under the state directory (`hosts/<name>.json`, additive field, no new state file), is cleared by the next `host sync`, never ages out by itself (nothing runs on a schedule), and is shown in `host list` and `status` for superusers. It is the first engineer-tier write, so it also needs a sudoers row, the TIERS man block and the upgrade's tier pin. | proposed: defer until a demand signal |
| D178 | Action pins are bumped in one batch at the start of a release, only for releases two weeks old, with the `test` and `release-reproducible` workflows green on the pull request as the proof. First candidate: `upload-artifact` 7.0.2 (eligible 2026-10-21). | proposed |

## 3. Candidates weighed

**A hold that follows `device address` (WP14.1).** The refusal is a few
lines in `internal/cli/device.go` (the address change under a hold) and the
rename already carries a record (`holdCarry`, `internal/cli/breakglass.go`).
The difference from a rename is that the address is what the renderers carve
out of every scope, so the move needs the render and the restart of each
backend and the address checks of `holdCheck` on the new address. Touches
`device.go`, `breakglass.go` (a move beside the carry), `docs/cli/device.md`,
`docs/cli/breakglass.md`, the man page, about six tests. One session.

**A hold for an enrolled Linux host.** About two sessions for low value and
a medium lock-out risk: the mechanism itself is unchanged (a hold is
`breakglass_hold.<name>` in `tacctl.yaml`; the address resolves through the
registry), but the refusal for hosts, the orphan and JSON helpers, the
`host` listings and `status` all assume a device. Closed (D176).

**A request-sync queue.** Two to three sessions, mostly design (D177).

**Left as documented.** The restart that follows a render sits inside the
apply lock; a failed restart leaves the new files and the old daemon, and
the reports say so. Undoing the render would restart a daemon on the old
files and can fail again, which leaves less than now.

## 4. Gates

Each WP: build, gofmt, `go vet`, `make lint`, the Man tests and the
`internal/cli` run green before the next starts. WP14.1: a test for each
refusal of the new address; a test that a failed restart leaves the registry
and the record on the new address with exit 1 and `NOT restarted`; a bats
case that holds a device, changes its address and reads the rendered files;
the diff corpus shows only the address line and the hold comment moved; the
container matrix (`fresh`) observes the render. WP14.2: both workflows green
on the pull request and the release notes name the new pins. At release:
bats, the diff corpus against 0.2.13, the container matrix, and the `test`
workflow on the release pull request.
