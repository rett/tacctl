# tacctl 0.2.22 plan (2026-10-29)

State: built on `feature/0.2.22` from the 0.2.21 merge into `develop`;
CHANGELOG `## 0.2.22 (unreleased)` items 1-18 are in, items 19-20 and a
sweep of the man page and user docs are in progress. Decisions continue the
numbering of the earlier plans (D284 and up). Scope chosen 2026-10-29.

## 1. Scope

The release is a round of defects found on a live network and the clean-ups
that go with them, plus the `server` command family queued after 0.2.21. No
new device write path, no credential, nothing scheduled or automatic.

| Item | CHANGELOG | What |
|---|---|---|
| Host-key read | 1 | A device `ssh-keyscan` reads nothing from gets the built-in client once |
| Virtual chassis | 2 | A Junos chassis whose master answers without a label is applied to |
| User names | 3 | Letters, digits, `_` and `-`; a leftover dotted name stays readable |
| Colours | 4 | Command names in the lists are teal like sub-commands |
| Lists | 5-7 | `host list` parity, `device list` devices only, `device list --differs` |
| `--yes` | 8 | The `-y` shorthand is gone, no alias |
| Concurrency | 9-10 | `host sync\|check --concurrency <n>` |
| Unknown words | 11-12 | One short answer; answered before sudo below the first word |
| `server` family | 13-17 | `server show\|listen\|metrics\|name`, `rollback 0.2.21` |
| Drop-in text | 18 | The generated drop-in and unit comments name the current commands |
| Timing scale | 19 | In progress: `timeout-scale` per device, scope and globally |
| Phase timing | 20 | In progress: `--timing` in the batch summaries |

Out of the release, decided: lockdown on enrolled hosts, naming a device
from its configuration, `device clone` and `rename --replace`, the SNMPv3
user pool, an email address on users (all `backlog.md` section 3j, for
0.2.23), several server addresses and failover, several addresses per
device, multiple shared secrets, the logging release, completion phase 2
and device reports.

## 2. Decisions

D284. Host-key read. `ssh-keyscan` prints nothing for a refused, filtered
or never-greeting target and a line only for a name that does not resolve
(OpenSSH 9.6, checked); its parallel connections starve each other on a
device that is slow to start sshd. When it reads nothing and printed no
resolver failure, the built-in client reads the keys one connection at a
time (`devssh.ScanTiming`: 3 s TCP connect, 10 s handshake, 5 s per key
type). A refused device fails at once, a filtered one costs the connect
budget, an unresolvable name costs one `ssh-keyscan`. The legacy-ssh path,
`enroll`, `collect` and the diagnosis after `ssh` exits 255 are unchanged.

D285. Virtual chassis. A label owns every line up to the next label. The
member with no label is the master: its answer is the lines before the
first label plus one final `commit complete` that reads as part of the last
group. Exactly one set member may lack a label; every other shape is
refused naming the member and the line. Observed on a three-member chassis
for `commit check`, `commit confirmed` and `commit`.

D286. User names. New names are letters, digits, `_` and `-`. A name with a
period cannot be a Linux account name and every user has an account since
0.2.21. Existing dotted names stay readable (older builds fail every store
command on one) so `user rename` can fix them; `config validate` reports
them and `upgrade` refuses. The rollback refusal for dotted names stays.

D287. `-y` is removed with no alias. `--yes` stays. A guard test and
`tests/tools/no-short-yes.sh` keep a one-letter spelling from coming back.

D288. Lists. `device list` shows network devices only; enrolled hosts,
including this server, are in `host list`, which gets the columns and
filters of `device list`. `--vendor linux` goes. `device list --differs`
is computed from the pull records, read-only tier excluded as for `--scan`.

D289. Concurrency. Several hosts run side by side for the ssh steps;
everything that writes on this server runs one host at a time. No terminal
and no questions with several hosts, so removed users' homes are kept
unless `--remove-home`. Any interrupt cancels the whole run (status 130);
a script already running on a host may finish, since nothing reaches it
without a terminal. Registrations that share an ssh target run one after
the other. `--timeout` and `--max-failures` are not offered: a time limit
would cut a script off in the middle of its account changes.

D290. Unknown words. One helper answers an unknown sub-command (error,
`Did you mean`, one `Run ... -h` line). Below the first word, a word that
is not a sub-command of a command with fixed sub-commands is answered
before sudo asks for the password. The walk looks at fixed words only,
never at names, flags or values, and reads no state. Words after a name or
value still go to sudo.

D291. `server` family. `config listen` and `config metrics` move, whole,
to `server listen` and `server metrics`, with no alias. `server name`
adds the key `server.name`, which a 0.2.21 build cannot read, so every
older rollback target removes it and `rollback 0.2.21` exists.

D292. Drop-in text. The generated tacquito drop-in and the shipped unit
comments name the current commands. A drop-in that differs only in a
comment is rewritten, systemd is reloaded and tacquito is restarted once
by the first render after the upgrade (checked by a test); after a
rollback the older release reports the rendered config as out of date
until its first render. Accepted for the correct text.

D293. Corpus markers. The `@known` markers of the differential corpus
record differences from the parity baseline 0.1.18 and are never pruned;
the `drop the marker` notices printed against a later tag are expected.

D294. Timing scale (in progress). One whole-number scale from 1 to 10
multiplies the network timings used to reach a device: the host-key scan,
the ssh and NETCONF connect, the SNMP timeout (within its maximum) and the
default pull timeout (within its bounds). Resolution: device, scope,
global, as for the NETCONF service setting; confirmed-commit windows are
never scaled; 1 changes nothing.

D295. Phase timing (in progress). `--timing` is opt-in; it reports the
time between the progress steps of each device (connect, login, read or
load, check, commit, confirm or verify) and the slowest device; nothing
is stored.

## 3. Checks and release steps

Every series on the branch passed `make gate-go` on the tree that was
pushed, and was reviewed by a second model with the findings folded in.
Not run on the combined tree: the whole bats suite, `tests/diff/run.sh
--all --against 0.2.21` (the `@known` lines for the moved and removed
words are unverified), the container matrix, `make gate-ci` (race and
`-tags testknobs`).

Release: `make gate-ci`, bats, corpus and containers; CHANGELOG item count
and a `grep` of each new verb; renumber nothing late; clear `dist/release`
before building the assets; the site pages for 0.2.22 wait for the tag
(`gh-pages`, `release_sync.py`); delete this plan in the release that
ships it.

## 4. Compatibility

A 0.2.21 build cannot read `server.name` (D291) or the timing scale keys
(D294). `tacctl rollback 0.2.21` removes them, converts nothing else and
needs no `--yes`; a dotted user name or an emergency lockdown does not
stop it. Upgrading from 0.2.20 or 0.2.21 with a dotted user name stored
replaces the binary and the tacquito build, then refuses: rename the user
and run `tacctl upgrade` again.
