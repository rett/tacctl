## 0.2.3 scope (backlog §0, as planned; the CHANGELOG records what shipped)

   Known gaps to close:
   - `internal/hosts/check.go`: `TacGroups`/`HostGroups` (used by `host show

   - D14: `group junos <g> list` for the read-only tier. The tier gate only
     sees two words (`tier.Permits(t, cmd, sub)`), so opening it means
     teaching the gate a third word or adding a read-only verb.
   - Review the WIP as a whole: it was never reviewed or integration-tested.
     Then run lint, all bats as user `tester`, the diff corpus against 0.2.2
     (mark every difference `@known 0.2.3 item N: ...`), and the container
     matrix (the client script changed: `hosts/run.sh ubuntu-noble tacplus`,
     `ubuntu-noble switch`, `almalinux-9 radius`, `radius/run.sh
     ubuntu-noble`).
2. **Junos-style spaces at the console/shell prompt** (`internal/shell`):
   a repeated space is refused silently (start of line, after or before a
   space; quotes keep spaces; pastes unchanged); a space completes a fixed
   word (commands, subcommands, fixed choices, flag names) when the match is
   unique; ambiguous lists the candidates (open: or stay silent); no match
   inserts the space; never in free-text positions or while pasting;
   `console space-completion on|off` (open: server-wide or per user).
3. **Provisioning-account rotation for Linux hosts**: create the new account
   over the current session, prove it with a fresh login that reaches root,
   switch the target (as `host target` does), optionally remove the old
   account last; refuse to remove the account in use. Sketch: `host
   provisioner <name> rotate <user> [--key <file>|--password] [--remove-old]`.
4. **Lab acceptance carried from 0.2.2**: Cisco (the lab router: the AAA
   block, per-level authorization, `config-commands`, the engineer's 58-rule
   blocklist, whether tacquito falls through to the next rule of the same
   name when a `--match` misses) and WTI (Service Name `wti`, per-group
   levels).
5. **Upgrade steps for 0.2.2 → 0.2.3** in the release notes: WTI Service

## Release procedure (git-flow again, from 0.2.3)

`release/0.2.3` from `develop` (release date, man `.TH` version, release
notes `docs/release-notes-0.2.3.md`); merge into `master` as
`Merge branch 'release/0.2.3'`; tag `0.2.3` with the same message; merge
back into `develop`; push `develop`, `master`, the tag; delete the release
branch; `make release-assets`, sign `SHA256SUMS`, `make release-verify`,
`gh release create 0.2.3 --title 0.2.3 …`; `fresh/run.sh --release 0.2.3`;
the dev server on master. The 0.2.1 and 0.2.2 GitHub release titles are to
be renamed to the bare version by the user (`gh release edit`).

## Working rules

- Commits are authored as the user through the repo's git config; no
  Claude attribution or session URLs in commit messages;
  `commit.gpgsign false`.
- Push only to the branch being worked on (`feature/0.2.3`); merges into
  `develop`/`master` and tags only when the user says so.
- No private names in repo files or commit messages (host names, addresses,
  user names, home paths, domains): use roles ("the dev server", "the lab
  switch", "the test VM", "the production host") and `example.*`,
  `192.0.2.x`. `make lint` runs `tests/tools/no-private.sh`; the user's
  pre-push hook also checks with `~/.config/tacctl/private-patterns`.
- Never act against the production host; give the user steps instead.
- Tests sandbox host paths. Bats run as user `tester`
  (`su tester -c "cd <repo> && tests/bats/bats-core/bin/bats <files>"`), with
  `make build` first. Go tests need `LANG=C.UTF-8`.
- Subagents work in worktrees and never commit; the coordinator reviews,
  merges, renumbers CHANGELOG items and commits. A worktree may start from
  the wrong commit: have each agent check `git log -1` and reset to the
  branch tip first.
- CHANGELOG: one numbered item per change under `### What changed`, bold
  lead sentence, plain prose; diff-corpus markers name the item number.
- Containers need rootless podman, Go in `/usr/local/go`,
  `/usr/local/bin/tacquito` (copy it from the dev server) and
  `python3-bcrypt` on the machine that runs them.
