## Scope (backlog §0, the 0.2.5 row)

The mission (user, 2026-10-10, verbatim): "we will not be deploying
configurations directly to devices for now, but we do need it to be as
straightforward and simple as possible to get exactly the right config to
paste for each device, we don't have time to uncomment, evaluate and
carefully select lines, and we can't expect our lower-level techs to be
consistent, so this is our way of showing irregularities and presenting
commands to establish consistency."

`tacctl device config plan`: for a device that has been pulled, first the
irregularity report in plain words (what is missing, different, out of
order, extra, not visible, not plannable for this login; what the paste does
about each; the severity), then one delimited paste region a technician
copies once and pastes once, with nothing to select or uncomment: on Junos
`configure private` … `show | compare | no-more`, `commit check`, ending at
`commit confirmed N` so the paste itself cannot make a permanent change; on
IOS `configure terminal` … `end` on every image (no revert timer: on 15.6 it
does not revert when the arming session is lost); the check and the single
follow-up line (`commit`, or `write memory`) outside the region; the
back-out as comments; with `--converge` a second, separately delimited cleanup
region that removes extras after the first is verified; secrets pasted only
when the device lacks them, the sections the caller's class cannot commit
simply absent with one report line; `--plain` for `load set <file>`,
`--json`, `--out`/`--out-dir` at 0600; Cisco as the same delta on the live
IOS 12.4 and 15.6 findings (`0.2.4-spike.md` "Legacy IOS 12.4" and "IOSv
15.6(2)T": the region `configure terminal` … `end` with the `no`-line
back-out as comments, no revert-timer region, the AAA lock-out guards, the
stored forms and the 15.x privilege residue tolerated; `--wrapper replace`
dropped; "lab-tested on IOS 12.4(15) and 15.6(2)T"); the Cisco rendering
dialect as a fact of its own (`device config-syntax auto|ios12|modern`,
resolved from the setting or the pull's `show version` line; `legacy-ssh`
means the ssh algorithms only; a release blocker found on the lab 15.6 and
IOS-XE 16.7 devices, D113); ITP 2811 routers as vendor `cisco`, dialect
`ios12` by D113, with the `cs7` privilege modes ignored by the extractor
(D114); Cisco ASA deferred to a later release (`asa-deferred.md`); **the
standard Cisco block** (plan §13, D116-D120, approved by the user): the
AAA standard tacctl renders, compares and plans (the `CONSOLE` list, exec
authorization giving the level, `aaa authentication enable … enable` so
nobody types `enable` with the server up, command authorization last,
the plain names kept, nothing renamed, the legacy server form handled
lock-out-safe), the hardening lines as a walkthrough-only checklist, one
new scope setting (`cisco.source_interface`); WTI
refused until 0.2.6;
`tacctl rollback 0.2.4`. `device config show` stays the fresh-device
walkthrough. Nothing is written to a device by tacctl.

## Working rules

- Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides
  important design questions. Subagents never commit; the coordinator
  reviews, merges, renumbers CHANGELOG items and commits.
- Commits only when the user asks in the current turn; push only to the branch
  being worked on; merges into `develop` and `master`, tags and releases only
  when the user says so. **No Claude attribution or session URL in commit
  messages.**
- No private names (hosts, addresses, users, home paths, domains) and no
  description of any installation's state or rollout in repo files or commit
  messages: use roles ("the dev server", "the lab switch") and `example.*`,
  `192.0.2.x`. Do not describe a release as lab-only.
- Never act against the production host and never connect to a production
  device. The lab switch is live-testable by the coordinator under the
  posture of `0.2.5-execution.md`: a load only in `configure private`, ended
  with `rollback 0` and `exit`; `zz-tacctl-*` names for anything created;
  **no commit of any kind** (the user's go-ahead covers private loads only);
  `gotest*` accounts against the dev server. The lab router (IOS 12.4): reads
  at will; a write (plan §8 C2-C5, the acceptance paste) only with the user's
  go-ahead for that run, a baseline copy and a held privilege-15 session
  first, backed out with the emitted block, compared with the baseline
  afterwards, every `tacctl-*` file deleted, never `write memory`.
- The region never contains `breakglass`, `netconf`, the lo0 application, the
  `access-class` binding, root authentication, the ssh service, groups or
  apply-groups, `username`, `enable secret`, a `line` header, a plain
  `commit`, `exit`, `rollback`, `write memory`, `configure confirm`, `copy`,
  `delete /force` or `load override` (the whole-paste invariant, plan D103
  (2)), and never deletes a statement outside the objects tacctl names
  (plan §4, §4b; the cleanup region's list in D111). A change to any of
  these lists is a Fable decision, not an implementation choice.
- Every user-visible change gets a numbered CHANGELOG item and updates
  `man/tacctl.1` and `README.md` in the same change (`make man` rewrites the
  generated blocks of the man page).
- Tests sandbox host paths; the fake device is the only device the tests
  dial; test knobs exist in test builds only.

## Gates

Build, gofmt, `go vet`, `make lint GOLANGCI_LINT=<path>` (includes
`tests/tools/no-private.sh` and the man tests), `go mod verify`, `groff -k -ww`,
Go tests with coverage (internal/cli needs `setsid -w ... < /dev/null`, a
scratch `GOCACHE`, Go in the PATH), all bats as the invoking user, the diff
corpus `tests/diff/run.sh --all --against 0.2.4` (every difference needs
`@known 0.2.5 item N`), the hosts container case once (the sudoers drop-ins
change), then the live acceptance on the lab switch (plan §8, WP13.5).

## Release procedure (git-flow, `docs/releasing.md`)

`git flow release start 0.2.5` from `develop`; the release date in the
CHANGELOG heading, the man page `.TH` date and version, the release notes
`docs/release-notes-0.2.5.md`; `git flow release finish -m "Release 0.2.5"
0.2.5`; re-tag with `git tag -f -a 0.2.5 -m "Release 0.2.5" master`; build,
sign and verify the assets; push `develop`, `master` and the tag; `gh release
create`.
