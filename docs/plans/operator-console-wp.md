# tacctl 0.2.1 / 0.2.2: operator console — work packages (plan of record)

> **Status: plan of record for implementation, written 2026-10-04 against `feature/0.2.1` at `b2492b1` (0.2.0 released the same day).** It refreshes `docs/plans/operator-console.md` (the design, all §12 decisions accepted 2026-10-03, plus the 2026-10-04 decisions) against the Go code and splits it into work packages in the shape of `docs/plans/go-rewrite.md` §9. Where this document and the design disagree, this document wins; the design stays the rationale. Markers: **[V]** verified by reading code or a read-only command; **[I]** inferred; **[A]** assumption to confirm in the package named.
>
> Numbering continues the rewrite's: **WP6.x = 0.2.1**, **WP7.x = 0.2.2**, WP8.1 = the optional 0.2.3.

## 0. Summary

1. **The rewrite delivered every §9.3 door-opener but one** (the `hosts` completion kind, deferred on purpose). The plan's package names and signatures are stale in detail (§1 lists each); nothing in the architecture needs undoing.
2. **Three findings change the design slightly** (§1.3): (a) the shell cannot resolve `ssh <name>` by itself (the registry is root-only), so `ssh` in the shell/console is an ordinary `sudo -n tacctl ssh <name>` line and the root side drops to the user — one code path, no second bridge (Open decision 1); (b) the bootstrap shim hard-codes `linux-amd64` for the Go tarball, so arm64 needs an architecture map before any release binary matters; (c) the tiers sudoers file must be refreshed on upgrade in 0.2.1 (backlog §3 item 5) or tier users cannot run any new verb until an administrator re-runs `config sudoers tiers install` — it is a prerequisite, not an optional fix.
3. **Release binaries:** sign `SHA256SUMS` with `ssh-keygen -Y` (ed25519, `release/allowed_signers` committed); assets built locally by the user with `make release-assets` (Go cross-compiles arm64 with `GOARCH=arm64 CGO_ENABLED=0`), signed locally, uploaded with `gh release upload`; the shim downloads only when the clone is at an exact tag and the signature, the checksum **and** the binary's stamped commit all check out, else it builds as today and says why. The Go toolchain stays required (tacquito is built from source on the host), so the gain is provenance and arm64, not a dependency removed. (§4.8, Open decisions 2–3.)
4. **0.2.1 = 14 packages, ≈ 15–17 sessions, ≈ 9,500 lines (Go + bash incl. tests)**; **0.2.2 = 5 packages, ≈ 6–7 sessions, ≈ 2,500 lines**; optional 0.2.3 ≈ 1–1.5 sessions (§8).
5. **Six open decisions** (§7), each with a recommendation, and the parity accept/reject table (§7.2).

### 1.3 Findings that change the design

**(a) `ssh <name>` from the shell and the console needs the root side.** The design (§5.3, §6.2) has the unprivileged shell exec `ssh` directly after resolving the name — but `devices.yaml` is root 0600 and the tier filter needs the model. A new privileged bridge (`_ssh-argv`) would be a second path to audit. **Recommendation (Open decision 1):** in the shell and the console `ssh <name>` is not special: it is the line `sudo -n /usr/local/bin/tacctl ssh <name> …` like any other; the root side resolves, applies the tier/scope gate, logs `ssh user= device= addr=`, and runs `ssh` as `SUDO_USER` through the existing `AsUser` runner (exactly as `host` does). Consequences: one implementation for `tacctl ssh` from bash, from the shell and from the console; the console's audit line comes from sudo for free; **the tiers sudoers lines must carry `SETENV:`** so `SSH_AUTH_SOCK=… tacctl ssh` passes `env_reset` (in the console agent forwarding is off by default, so there is nothing to pass); the console-specific hardening (`-F /etc/tacctl/console/ssh_config`, `EscapeChar none`, no `--` passthrough) is applied by the root side when the line carries the console marker (`--console <session>`, design §6.7) — so 0.2.2 needs no second ssh path either. Part B therefore has **no built-in but `help`, `history`, `exit`/`quit`**, and Parts B and C decouple (they can be built in parallel).

**(b) arm64 is blocked before the binary.** `bin/tacctl.sh:138` downloads only the amd64 Go tarball. WP6.8 adds `uname -m` → `amd64|arm64` for both the Go tarball and the release asset; anything else builds from source with Go already present or fails with the existing message.

**(c) Tiers sudoers refresh on upgrade is a 0.2.1 prerequisite.** New rows (`ssh *`, `device list|show|ssh-config`, `device check|scan|discover|export`, `_completion-names` already there) are generated into `tier.Sudoers()`; without a refresh an installed `/etc/sudoers.d/tacctl-tiers` keeps the 0.2.0 aliases and readonly/operator users get `sudo: a password is required` on every new verb. Backlog §3 item 5 moves from "candidate" to required (§7.2, item 5): `upgrade` rewrites the file when it exists and differs, through the same `visudo -cf` path as `install`, and reports `Updated: tiers sudoers`.

**(d) Smaller corrections.** The shell's per-line command is `sudo [-n] <a.Exe> <tokens>` where `a.Exe` is the resolved executable (in production `/usr/local/bin/tacctl`, the path the sudoers aliases name; in the bats harness `dist/tacctl` with a stubbed `sudo`); `-n` only for tier-managed callers (member of `tac-users`, checked with `id -nG` as `tier.Gate.Caller` does), plain `sudo` for administrators so sudo's own prompt and 15-minute cache apply. The hidden `--console <session>` marker of §6.7 is stripped by `cli.Run` before `resolve` (one place) — needed in 0.2.2 only. `device add` pins host keys with `ssh-keyscan` through the runner; the `SHA256:` fingerprint is base64(sha256(key blob)) computed with the standard library — no `x/crypto/ssh` import, no re-vendoring. Release-asset download and the Go tarball both use `wget` through the shim (bash) — consistent with the shim today; the Go side reaches it through `bin/tacctl.sh` as `Build` already does, so no HTTP client enters the Go binary and bats stubs cover it.

## 3. Common rules for every hand-off (restate verbatim in each brief)

- Read `README.md`, `tests/README.md`, `docs/plans/operator-console.md` (the design) and this document's package text first; use absolute paths.
- **Subagents never `git commit` or `git push`.** Stop at the working tree; report a file-by-file summary, the tests added/changed, and the lint/test commands run with their results. The coordinator commits at package boundaries when green, merges `feature/0.2.1` → `develop` when the release is done, and releases under the user's standing permission when the gate holds.
- **Green means:** `make lint` exit 0 (shellcheck, gofmt, `go vet` ×2, golangci-lint v2.14.0 ×2, `tests/tools/no-private.sh`), `make test-go` green with and without `-tags testknobs`, `make build && BATS_JOBS=8 make test-bats` green; **no test skipped or weakened**; a package that cannot reach green says why.
- **Go rules:** no `os/exec` outside `internal/execx` (depguard), no `os.Getenv`/`os.Environ` outside `internal/paths` and the knobs (forbidigo), no `os.Exit` outside `cmd/`; every program (sudo, ssh, ssh-keyscan, journalctl, logger, sshd, wget, ssh-keygen) runs through the runner so bats stubs and `execx/fake` work; every command returns an `error`; timestamps through `a.Knobs.Now()` so goldens are deterministic.
- **Sandboxing:** every new path is a `paths.Paths` field with a `TACCTL_*` override, added to `tests/helpers/tmpenv.bash` and to `hostDefaults` in `internal/cli/sandbox_paths_test.go`; no test may touch `/etc/tacctl`, `/var/lib/tacctl`, `/usr/local/bin`, `/opt/tacctl`, `/opt/tacquito-src`, `/etc/ssh`, `/etc/shells`, a real `~/.ssh` or logrotate.
- **Process hygiene:** no polling loops; never `pkill -f`/`pgrep -f` with a pattern that matches one's own command line; pty tests have a hard deadline.
- **No private names:** no personal host names, home paths, user names or domains in any repo file — "the dev server", "the test client", "the production host", `example.net`; `make lint` enforces it.
- **Documentation policy:** README, man page, help and completion describe current behaviour only; history goes to `CHANGELOG.md` (one numbered entry per behaviour change, as 0.2.0's list). Packages adding verbs update `man/tacctl.1` (the `TestManPageNamesEveryCommand`/`NoMissingCommand` tests fail otherwise) and the README's CLI reference for their own verbs only; `man/tacctl.1`, `README.md`, `CHANGELOG.md` are shared files whose conflicts are additive and resolved by the coordinator.
- **Live rules:** never the production host; live steps only on the dev server and the test client, only in WP6.11/WP7.4, snapshot first (`sudo tar czf /root/tacctl-pre-<ts>.tgz /etc/tacctl /etc/tacquito …`, plus `tacctl backup list` noted), throwaway accounts `gotest*` and throwaway registry entries `gotest-*` removed afterwards; the user types real passwords; `--scope lab` when re-enrolling.
- **Worktrees:** a "worktree: safe" package starts only after its dependencies are merged into `feature/0.2.1`; the brief states the expected `git rev-parse --short HEAD`; the agent checks it before working; worktree packages build into their own `dist/`; parallel packages own disjoint files; `internal/cli/root.go`, `Makefile`, `go.mod`/`vendor/`, `bin/tacctl.sh`, `tests/helpers/*.bash`, `internal/paths/`, `internal/tier/` are owned by exactly one package at a time (named below); a package needing a file it does not own writes the change into its report.
- **Secrets:** no real secret from `/etc/tacctl` or a dev host in a report or scratch file; fixtures use the existing placeholder secrets; the argv-recorder tests assert that no child argv of `ssh`, `sudo`, `ssh-keyscan` carries a secret.
- **Executor:** Opus for design- or security-sensitive packages, Sonnet for well-specified ports. Each package is sized for one session unless stated.

### 4.10 WP6.8 — Release binaries (download, verify, fall back to build)

- **Read first:** backlog §2; `bin/tacctl.sh` whole; `internal/lifecycle/{build,install,upgrade}.go` (`Build`, `installCommand`, `selfUpdate`, `updateDeploy`), `tests/integration/shim.bats` (the 15 shim tests), `tests/containers/fresh/run.sh`, go-rewrite §5.1–5.3 and §3.9 items 23, 26, 27; `ssh-keygen(1)` `-Y sign|verify`, allowed_signers format.
- **Decisions this package implements (Open decisions 2 and 3; recommendations):**
  - **Signing: `ssh-keygen -Y` with an ed25519 key, not minisign.** Reasons: `ssh-keygen` is on every host that has `openssh-client` (the hosts tacctl manages do), is already used by the project's operators, needs no package in the shim's bash path on a fresh host, and its format is stable since OpenSSH 8.0 (2019; RHEL 8 ships 8.0p1, Debian bookworm 9.2, Ubuntu noble 9.6 — all fine). minisign needs a package or an in-process verifier in Go (not usable in the bash shim) and adds a dependency. Verification in both the shim and (through the shim) the Go side is `ssh-keygen -Y verify -f <tree>/release/allowed_signers -I <signer-identity> -n tacctl-release -s SHA256SUMS.sig < SHA256SUMS`, exit 0 required. The public half is committed as `release/allowed_signers` (`<identity> namespaces="tacctl-release" ssh-ed25519 AAAA…`); the identity string is the project's release identity (`tacctl-release@example.net`-style placeholder is **not** allowed by the no-private rule — use a non-address identity such as `tacctl-release`).
  - **Assets built locally by the user, not by CI.** Reasons: Go cross-compiles both targets from one machine in seconds (`GOARCH=arm64 CGO_ENABLED=0`), the build is already reproducible (`-trimpath`, fixed toolchain, stamped from git; go-rewrite §5.1), no secret or trust leaves the user's machine, and there is no `.github/` today. `make release-assets` runs `bin/tacctl.sh --build dist/release/tacctl-<tag>-linux-<arch> --goarch <arch>` for `amd64 arm64` and writes `dist/release/SHA256SUMS`; the user signs and uploads (steps below).
