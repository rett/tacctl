## State

gates it passed). `develop` carries the tag and the test-only
`shortLockWait` change that followed it.

holds the plan and this note only. The scope, chosen 2026-10-18 and
designed the same day, is ten items in `0.2.15-plan.md` section 1:
`backup restore` refuses while a host is locked and takes `--keep-uids`;
the snapshot dedupe ignores a record's `last_sync` and `facts`; `host sync`
takes several names and `host check <name>... | --all [--json]` is the
read-only batch; `config validate --json` and `--fix-names`; the small
fixes of D222; the `--hold` answer race behind the `device_apply.bats` #13
flake (D223, D224); and WP15.0, the action pin bump, which runs at release
start on or after 2026-10-21 (D178, D225).

Open before building: the three choices of section 3 of the plan that the
maintainer may still turn (a held host typed by name in `host sync`,
D215; `host check` with names, D216; a per-section status in the JSON,
D220), and whether WP15.9 (`--fix-names`) stays in this release.

Direction: every operation is started by a person; tacctl holds no device
credential and runs nothing on a schedule (`0.2.12-plan.md` section 2).

## Working rules

- Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides
  important design questions. Subagents never commit; the coordinator reviews,
  merges, renumbers CHANGELOG items and commits.
- Commit when appropriate (a coherent unit of work that has passed its
  gates); ask before pushing, and push only the branch being worked on;
  merges into `develop` and `master`, tags and releases only when the user
  says so. No Claude attribution in commit messages.
- No private names (hosts, addresses, users, home paths, domains) and no
  description of any installation's state or deployment in repo files or
  commit messages: use roles ("the dev server", "the lab switch") and
  `example.*`, `192.0.2.x`.
- Never act against the production host and never connect to a production
  device: prepare the files and let the user apply them.
- Every user-visible change gets a numbered CHANGELOG item and updates
  `man/tacctl.1` and the matching `docs/` page in the same change.
- Gates: build, gofmt, `go vet`, `make lint`, Go tests (`internal/cli` needs
  `setsid -w ... < /dev/null`, a scratch `GOCACHE`), bats as the invoking
  user, the diff corpus against the previous release, the container matrix,
  `groff -k -ww`; the `test` workflow on the pull request. Tests sandbox
  host paths, and a test must not read a path of the machine it runs on.
  A test that needs the process environment or a package-wide registry calls
  `serial(t)` first; the others run in parallel (`hooks_test.go`).
- A release: `docs/releasing.md`. The release branch is pushed and a pull
  request opened to `master` so the Go tests run before the tag.
