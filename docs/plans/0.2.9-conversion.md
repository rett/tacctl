# tacctl 0.2.9: conversion map of the helper script (2026-10-13)

> Companion of `0.2.9-rollout-plan.md` (D128-D144). The helper is a 1,913-
> line bash script, outside the repo, that drove phased Junos rollouts by
> hand from a tacctl server: `doctor`, `discover`, `collect`, `register`,
> `sync`, `plan`, `review`, `rollout`, `onboard`/`bootstrap`, `shapes`,
> `seed`, `batch`, `archive`, `status`. This file says, per phase and per
> non-trivial function, where it goes in tacctl ("becomes", "folded into",
> "dropped, because"), which of its subtle behaviours are kept or changed
> on purpose, what in it must not be carried over, how the fake device
> learns to stand in for a switch, and how an installation that used the
> helper moves to the verbs. Markers as in the plan: [V] read in the code,
> [S] settled on record, [L] for the lab, [A] an assumption. Names in the
> helper's own header (its scopes, hosts, accounts) are not carried over.

## 1. Phases

| Helper phase | Disposition |
|---|---|
| `doctor` | **dropped, because** its checks exist: `tacctl status`, `config validate`, `breakglass list`, `config devices` (the confirm timeout), `backup list`; its tacctl-version test is moot (one binary); the "is the login user the sudo user" warning is the pull's rule [V: `configLogin`] |
| `discover` | **folded into** `device discover` [V: the unregistered table] plus `device collect --discovered` (D137); the TCP banner probe per address is dropped: `collect`'s dial reads the banner (`Client.ServerVersion()` [V]) and legacy ssh is learned from the handshake, not guessed from an OpenSSH version |
| `collect` | **becomes** `device collect` (D137): one login per address, `show version` and the pull's read command, a table, the `device add` lines |
| `register` | **folded into** `device collect --register` (the registry's own `device add` path: every offered key pinned [V: `deviceAddKeys`], the login's key cross-checked [V: `CrossCheckKeys`], `--legacy-ssh` from the handshake) |
| `sync` | **becomes** `device sync` (D137): from the records, no login, no python, one registry write under the lock |
| `plan` | **folded into** `device config pull --diff` and `device config plan` (they exist); the rollout works from the record and recomputes the delta, so no plan files are written for it (`--out-dir` stays for pastes) |
| `review` | **folded into** the one review prompt of `device rollout apply` (D134): the delta grouped by shape, the login-path lines, the lo0 note, the kept lines, the soft guards; the sha256 and the age become `Delta.Equal` between the phases (D83) and a re-read of the device |
| `rollout` | **becomes** `device rollout check` (stage A) and `device rollout apply` (stages A and B, D131) |
| `bootstrap`, `onboard` | **become** `device onboard` (D136), with `device config pull|diff|plan --login` as the building block the backlog asked for |
| `shapes` | **becomes** `device rollout shapes [--show]` (D135), from the records, no device contacted |
| `seed` | **becomes** `device rollout seed <name>` (D135): the device's last check's shape, by the person's word |
| `batch` | **becomes** `device rollout apply --confirmed [--max N] [--pause <s>] [--yes]` (D130, D139); the child-process `ROLLOUT_AUTO` mode is gone: one process, one pool, one password |
| `archive` | **dropped, because** no raw device output is stored (D138): there is nothing to archive; the audit log and the records are the history |
| `status` | **folded into** `device config list` (the `APPLIED` column) and `device show` (the rollout row); `log search 'device rollout'` is the `rollout.log` tail |

| `cmd_archive` | **dropped** |

| `log` (`rollout.log`) | **becomes** the audit lines (D141) |
| `usage`, the `--dir`/`--login` option loop, the root refusal | **become** the specs and the `--login` gate (D136, D141) |

## 3. Subtle behaviours: kept or consciously changed

Each line says what the helper does, what 0.2.9 does, and why where they
differ.

1. **Root's csh and the wrapper** `sh -c 'PATH=$PATH:/usr/sbin:/usr/bin:
   /sbin:/bin; exec cli'` as the remote command: **kept** as fixed text in
   `devssh.WithCommand`, used only when the login is `root` [L4: the prompt
   and echo without a pty]. The helper's `ROLLOUT_ROOT_CLI` override is
   dropped: a wrapper that does not work is reported with the helper's
   own advice (type `cli` at the `%` prompt by hand) and a backlog note.
2. **`configure exclusive` by default, `--private` on request; the
   private refusal of `commit confirmed` on some releases detected by
   text:** **kept** (D131 steps 4 and 8), with one change: the session is
   held through the confirm instead of reopened for it.
3. **The idle-timeout per-class fallback** for releases before `system
   login idle-timeout` existed: **changed**: no rewrite of the plan; the
   renderer consults 0.2.8's gate table with the recorded release (D144).
   Consumed from 0.2.8: `Record.Release`, the gate table, the "no release
   recorded: the current form" rule. What 0.2.9 adds: the check failure
   text that names the gate and asks for a second run.
4. **`statement not found` handling**: the helper swallowed it for one
   statement shape (`delete snmp community <name> clients <addr>`) and
   failed on every other. **Changed**: it is a warning for any `delete`
   (the device's own word for an absent node [S]), counted and shown; an
   error for anything else.
5. **A `commit check` from any session confirms a pending confirmed
   commit**: **kept** as the reason for the pre-flight's pending test, the
   refusal of `check|apply` on a pending device, and the operator's text
   (D132). The helper refused every rollout on the server while any device
   was pending; 0.2.9 refuses the pending device only.
6. **The `uid N;` line** that Junos adds to the landed compare of a login
   user it created: **kept** as a rule of `CompareText.Normalise` [L3].
7. **Legacy ssh algorithms by banner** (OpenSSH < 7.2): **changed** to the
   registry's flag, set by `collect` when the first handshake fails on
   algorithms and the legacy one succeeds [A]; the dial is `devssh`'s with
   `Target.Legacy` [V].
8. **One password attempt per device and `MAX_AUTH_FAIL`** (stop after one
   refused login): **kept** by construction [V: `passwordMemo`,
   `StopOnAuthFailure`].
9. **Host-key CHANGED refusal** (a key that differs from the one trusted
   earlier): **kept** by `devssh` (ErrHostKey against the pinned keys [V]);
   `collect` and `onboard` never rewrite a pin; `device hostkey accept` is
   the person's act.
10. **The name-mismatch refusal** (the reported `Hostname:` against the
    registry name, lowercased, bypassable by an environment variable):
    **changed**: the tolerance of backlog §3d (the registry name, its first
    label, the registry's `hostname` field, its first label), no override.
    The helper's exception for a bootstrap plan that sets `host-name` is
    moot (D136 step 5 emits none).
11. **The staged/other-editor gate** before the check, before the apply
    and before the confirm: **kept once** (before OPEN) and then replaced
    by the exclusive lock held to the confirm (D131). The helper's gate
    reads the shared candidate in a shared session that only reads and
    exits: kept exactly, because an exclusive session's exit would discard
    a stranger's staged work.
12. **The window-short refusal under 45 s**: **kept at 60 s** (D131 step
    10), because the confirm's own round trip and `commit complete` need a
    margin on a slow switch.
13. **The exit codes 2-7** (nothing committed, verify login failed, not
    confirmed, window short, confirm blocked, landed mismatch) and 10
    (batch skip): **changed** to the batch's 0/1/2/130 [V] with the typed
    result in the line, the record and `--json` (`result`, `reason`): the
    helper's codes were for its own batch loop, which is now in-process.
14. **The confirm comment** `tacctl rollout confirm <dev> by <user>` and
    the commit comment `tacctl plan <dev> <time> by <user>`: **kept** in
    form, with the change identifier added (`tacctl rollout <id> by
    <user>`, `tacctl rollout confirm <id> by <user>`, `tacctl rollout
    cancel <id>`) so the history entry can be found.
15. **The pre-flight as the invoking user over an exec channel** (`show
    version`, `show system commit`): **kept**; `show cli authorization`
    added for `Confirms()`.
16. **The verification's order** (fresh login, `show system commit` entry 0
    pending, `show cli authorization`, the landed compare, then the
    convergence pull): **kept** in that order on one second connection.
17. **The batch's lower verification** (the helper's batch never ran the
    convergence check: `missing` was computed only when not in auto mode):
    **changed**: every device, batch or not, gets the same verification.
18. **The reviewed plan's sha256 and the 7,200-second review age**:
    **replaced** by `Delta.Equal` between Phase A and Phase B after a fresh
    read of the device (D83): the review and the apply are one run.
19. **The 1,800-second pull age behind a plan**: **replaced** by Phase A's
    own read (minutes old at most) and `stale-days` for `plan` alone.
20. **The bootstrap's refusal of a device that already has a server**
    (and the relaxation for SNMP and classes): **kept** (D136 step 2).
21. **The bootstrap's name rule** (the reported hostname unless generic,
    then a prompt; `--name`): **kept**, with `devreg.IsGeneric` [V].
22. **The bootstrap's registry fill** (location from `snmp location`,
    hostname from `host-name` + `domain-name` when the name has no dot,
    description from `snmp description`; never replacing a set value):
    **kept** (D136 step 3), and `device sync` does the same from records.
23. **`set system host-name <name>` appended by the bootstrap when the
    registered name differs**: **dropped** (D136 step 5): tacctl renders no
    host-name statement; the registry's `hostname` field carries the
    device's own name.
24. **The local-account probe after the commit** (does the local account
    still log in while the server answers): **kept**, informational.
25. **`--login root` accepted only for a first-time plan**: **kept** (D136).
26. **The collect's "login refused" hint** (a device whose authentication
    order is tacplus only refuses local users): **kept** in `collect`'s
    result line.
27. **The lo0 check from `collect`'s inventory column** (a filter applied
    on lo0 at collect time): **changed**: the planner reads the lo0
    application from the pull of this run [V: `lo0Check`], not from a
    table made in an earlier phase.
28. **The batch's pause between devices and `--max` applied devices**:
    **kept** (`device.rollout.pause`, `--max`).
29. **`sync`'s preview-first, `--apply` to write, `--overwrite` to
    replace**: **kept**.
30. **The helper's one global rollout lock per server**: **changed** to a
    per-device lock (D138).

## 4. What must not be carried over (defects, hazards, fragile parsing)

Each names the function.

1. **`check_region`**: a hand-kept regex allow-list that the planner's
   growth outran (0.2.7's system block had to be added by hand, B9 of the
   blocks plan) and that hard-codes class names (`RW-CLASS`, `super-user`)
   as the one allowed privileged exception. Replaced by `plan.Allowed`
   derived from the ownership tables (D133).
2. **`pull_age_seconds`**: parses the plan's word-wrapped prose header
   ("Based on the pull of ... (18 minutes ago; ...)") with a regex over
   the first 25 lines; a wording change in `plan` breaks every rollout.
   Dropped.
3. **`idle_to_classes`**: rewrites a reviewed plan file with awk, re-signs
   it (`sha256sum > reviewed/<dev>.sha256`) and re-runs the rollout: the
   new lines were never reviewed by the person. Replaced by D144.
4. **`cmd_rollout` stage A/B input**: the whole region is one stdin stream;
   errors are found afterwards by grepping the output, so a failure cannot
   be attributed to a statement and a `syntax error` under one line is
   matched by its caret two lines later. Replaced by one `Run` per
   statement.
5. **`ERROR_WORDS` over the whole output**: `out_has_error` greps the
   check's and the apply's output, which includes the `show | compare`
   text and, after 0.2.7, a `system login message` that may contain
   "error:" or "not authorized" (banner prose); a harmless compare then
   fails the check, and conversely `grep -qi 'commit complete'` is a
   substring test that a message could satisfy. Replaced by per-command
   matching against the statement's own output and required phrases on
   the commit's output only.
6. **`cmd_collect`'s banner filter**: `SSH-2.0-OpenSSH*` matches a Linux
   host; the TACACS+ password is then sent to it and the `show` lines run
   as shell commands there. Replaced by the registry's practice (an
   address the person names) plus `show version` as the first command and
   a close on anything but Junos (D137).
7. **`ask_password`**: the password lives in a file on tmpfs for the run,
   and in a batch for the whole batch (`ROLLOUT_PARENT_ASKPASS` hands the
   same file to every child). tacctl's rule is memory only, zeroed, with
   the cache's lifetimes [V: D70].
8. **`cmd_sync`**: exports the registry, merges in python, and re-imports
   the whole file with `device import -y`: a change made to the registry
   between the export and the import is overwritten. Replaced by one write
   under the registry's lock.
9. **`cmd_bootstrap`'s walkthrough parse**: `awk '/^commit/ {exit}
   /^(set|delete) / {print}'` over `device config show`, then `sed` to
   drop `delete system authentication-order` when the device had no
   order: the plan depends on the walkthrough's prose layout (the backlog
   names it as the fragile part). Replaced by the ordinary planner over an
   empty pull.
10. **`cmd_rollout`'s hostname check**: a device registered by its FQDN
    against a short `Hostname:` is refused unless an environment variable
    is set. Replaced by the §3d tolerance.
11. **`cmd_rollout`'s lo0 test** reads column 10 of `inventory.tsv`, data
    from an earlier collect, possibly days old. Replaced by this run's pull.
12. **`compare_shape_v1` and the dual filing in `shape_known`**: two hash
    generations kept for an old on-disk format, with a side effect (a read
    files a shape under a second name). Replaced by stored lines and an
    algorithm number.
13. **The `.pending` marker** refuses every rollout on the server while any
    device is pending, and is removed on expiry without reading the
    device. Replaced by the record's `pending until` and a read before any
    claim (D132).
14. **`cmd_batch`'s convergence check is skipped in auto mode** (`missing`
    is only computed when `auto == 0`): a batch confirmed with less proof
    than a hand rollout. Every device gets the same verification.
15. **The landed check through the TACACS+ login in onboard**: a class
    without rollback or view-configuration rights reads an empty compare
    and the shape mismatches, so the change rolls back for a reason that
    is not a fault [L7]. 0.2.9 reads the landed compare on the held session
    when the second login's class cannot.
16. **`device_field`, the convergence `awk` over `device config diff`'s
    human output, `cmd_register`'s `device list` parse, the discover table
    parse in `cmd_discover`**: tacctl's own text output parsed by column.
    None of it is needed in-process.
17. **`valid_addr` is IPv4 only**; `targets.txt` cannot hold an IPv6
    address the registry accepts.
18. **`cmd_doctor`'s version glob** (`*0.2.[7-9]*`) refuses `0.2.10`. Moot.
19. **`exit 2` for "nothing committed"** collides with the usage status.
    Replaced by the batch's statuses.
20. **The confirming commit from a new session** after a gate (two
    sessions, a race in between): replaced by the held exclusive session.

## 5. The test-porting plan

**What the fake device must learn** (`internal/devssh/fakedev`, D142):

- A Junos **configuration model** over the command line: a committed
  tree from `config.set`, a shared candidate, sessions in shared,
  exclusive and private mode (one exclusive at a time; a second `configure
  exclusive` refused with the holder; a private session's isolation; the
  `private.no-confirmed` knob for a release that refuses `commit
  confirmed` there), the configure prompt and the `[edit]` line, the
  `{master:0}` line (`switch` knob).
- `set`, `delete`, `insert ... before|after term` with per-statement
  answers (`load.errors`: `<prefix> <message>`; `delete` of an absent node
  answers `warning: statement not found`); the candidate as a tree with
  list and leaf semantics for the managed hierarchies (the 0.2.5 property
  test's in-memory editor [V: `simulate.go`] is the model to share or
  copy).
- `show | compare | no-more` in brace form from the candidate; `commit
  check` with `check.errors`; `commit confirmed N comment "..."` with the
  Junos line and a timer that rolls back at expiry (not at session close);
  `commit [comment]` confirming (`commit complete`); `commit check`
  confirming a pending one; `rollback 0|1`; `exit` (and `exit` with
  uncommitted changes in exclusive mode discarding them); `quit`.
- `show system commit` (entries with sequence, time, user, `via`,
  comment, `rollback in N minutes`); `show system rollback compare 1 0`
  (the brace diff between entries, with a `uid` line when a login user
  was created); `show version` (`Hostname:`, `Model:`, `Junos:`); `show
  cli authorization` from `class`.
- A **local account** beside the TACACS+ one (`local` file) and a **root
  login** whose shell is a csh prompt and whose `sh -c '...; exec cli'`
  exec starts the CLI (`root` knob); `verify.fail`, `commit.drop`,
  `dirty.shared`, `exclusive.held-by`, `version-gate` knobs; `committed.
  set` written after every commit.
- **Golden transcripts** in `tests/fixtures/devconf/juniper/rollout/`:
  the exact texts of L1-L5 sanitised (the configure prompt, the refusals,
  `commit confirmed`'s line, `commit complete`, the history, the cancel),
  which the fake answers with and the parser's tests read; until the
  spike lands, placeholders marked [A] from the helper's observed phrases.

**Go tests:** the plan's D142. **Bats:** the plan's D142. **The helper's
own evidence** (its observed phrases in `cmd_rollout`: `configuration
check succeeds`, `commit complete`, `commit confirmed will be rolled back
in`, `commit confirmed not supported for private`, `Users currently
editing the configuration`, `changed but not committed`, `statement not
found`) is the placeholder set.

## 6. The transition for an installation that used the helper

Generic, by role; nothing here describes an installation.

1. Upgrade to 0.2.9 (the sudoers drop-ins are rewritten for the askpass
   alias lines; nothing to re-paste).
2. The devices the helper registered are in the registry already; their
   host keys are pinned by `device add`; the helper's `known_hosts`,
   `inventory.tsv`, `plans/`, `reviewed/`, `raw/` and `shapes/` are not
   read by tacctl and can be removed once the steps below are done (the
   raw outputs and the archive tarballs may hold community and trap-group
   names: delete them as the helper's own text advises).
3. `tacctl device config pull --vendor juniper --diff`: fresh records.
4. `tacctl device rollout check --vendor juniper`: every device's shape
   from its record; `tacctl device rollout shapes` lists them, all new.
5. For each shape, one reviewed `tacctl device rollout apply <one device
   of it>`; the shape is confirmed by it. A device the helper rolled out
   and verified before, whose check shows a change the person knows was
   applied by hand, is `device rollout seed <name>` instead.
6. `tacctl device rollout apply --vendor juniper --confirmed --max 5` for
   the rest, batch after batch, as the helper's `batch` was run.
7. A blank device: `tacctl device onboard <address> --login <local-user>`
   with `--host-key` from its console.
8. The helper's `sync`: `tacctl device sync --vendor juniper` (preview),
   then `--apply`.
9. The helper is retired; its `check_region` allow-list, which the blocks
   plan's B9 extended by hand, has no successor to maintain.
