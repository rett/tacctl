# tacctl 0.2.17 lab sheet: one walk of `device enroll`

One run of `device enroll` (D261-D264, D271) on a lab Junos switch that
tacctl has not registered, made by the user from the dev server; never by
an agent and never against a production device. The Go tests and
`device_enroll.bats` pin every stage against the fake device; this sheet
checks what only a real device shows: the key on its console, the name it
reports by SNMP, a real pull and plan, and the apply review on a real
commit.

## Before

- The switch answers SSH on port 22 and SNMP with the scope's credentials
  (`tacctl device check` of a registered neighbour shows an SNMP name).
- Its address is in a scope's prefixes, and your account is a member.
- It is not in the registry (`tacctl device list --ip <address>` shows
  nothing) and no break-glass hold stands on it.
- On its console: `file show /etc/ssh/ssh_host_ed25519_key.pub` (and
  `ssh-keygen -lf` from `start shell`) gives the ed25519 fingerprint.
- `tacctl backup list` before the run, to count the snapshots.

## The run

1. `tacctl device enroll <address>` at a terminal.
2. The key shown under `Will pin` is the ed25519 key; compare its
   fingerprint with the console's. Type the name in parentheses.
3. The registration question names the vendor `juniper (the device says
   so)`; answer `y`.
4. The password prompt comes once; the pull's line and the plan follow.
5. At `Run the apply review ...` answer `n` the first time.
6. Run it again for a second address, or `tacctl device config apply
   <name>`, and answer the review with the device's name to see the
   commit and its proof.

## What to record

| Check | Expected |
|---|---|
| The fingerprint under `Will pin` | equals the console's ed25519 fingerprint |
| `tacctl device hostkey <name> show` | that one key pinned |
| `tacctl backup list` | one snapshot more than before |
| The table row | `KEY accepted`, `PULL ok`, `PLAN differs` or `ok`, `RESULT planned` |
| `journalctl -t tacctl` for the run's `sid=` | `cmd start`, `device enroll hostkey ... result=accepted source=confirmed`, `device add`, the pull's and the plan's lines, `device enroll ... result=planned`, `cmd end ... snapshot=<id>` |
| A typed name (repeat with SNMP off for the scope) | renamed to the device's `system host-name`, or kept with the reason |

## After

`tacctl device remove <name>` and `tacctl device config forget <name>`
return the registry to where it was, unless the device is to stay.
