# 0.2.7: configuration blocks, execution plan

Decided 2026-10-12: the configuration blocks of
`backlog.md` §0b ("Configuration blocks", both rounds of decisions) are built
in 0.2.7, not 0.2.8. Their design (layout, ownership by statement, resolution,
editing, the `system` block, the heredoc login message) is settled there and is
not repeated here; this file is the build order and the acceptance for each
step.

**Release content.** 0.2.7 is the SNMP community labels and `ok (+N unmanaged)`
(on `feature/0.2.7`, commits `1b16710`, `37549aa`), these blocks, and the WTI
half (it waits for lab run sheets, `wti-interface.md` §10).
0.2.7 ships when all three are done; the blocks do not wait for the run sheets
to be built.

**Scope of the blocks in 0.2.7 (decided 2026-10-12): Junos, complete.**
Scope-level and device-level `snmp` and `system` blocks for Junos, with `list`,
`show`, `check`, `set`, `remove`, `edit` and `adopt`. The IOS blocks
(`snmp-server` trap lines, `banner login`, `ip domain`, `clock timezone`, `ip
name-server`, `ntp server`) were planned for the release after, because the IOS
trap-group lines have no lab paste yet. The IOS `snmp` block was then built in
0.2.7 from the vendor's references, not lab-tested ("IOS snmp block as built"
at the end), and so were the IOS `system` block and the trap source of both
vendors ("IOS system block and trap-source as built"). The lab scopes only
while the feature is tested; the production scopes after a lab rollout of the
`system` block reads back clean.

## Ground rules for every package

- Junos syntax in a block is Junos `set` lines and nothing else; tacctl never
  translates between vendors. A scope with both vendors has two files.
- The stored pull never holds a community string: the marks of step A
  (`<secret:N>` for a string tacctl renders, now including a block's, and
  `<other:N>` for the device's own) are the only form that is stored, shown in
  `--json`, diffs or reports.
- Tests, fixtures and goldens use example names only (`js1.lab.example.net`,
  192.0.2.x, 198.51.100.x). No private names anywhere in the repo.
- Each package is one commit-sized change with its tests green, the CHANGELOG
  item, the man page and the README in the same change (`CLAUDE.md`).
- The coordinator commits. Nothing is pushed without an explicit instruction.

### B1. Block store

`<StateDir>/blocks/<scope>/<vendor>/<block>`: directories 0700 and files 0600
root, written atomically (temp file, fsync, rename), names checked with
`internal/names` (scope and device names must exist; a block name is a word of
`[a-z0-9-]`, `snmp` and `system` known, others refused until a block type
exists). `blocks.<scope>.<vendor>: [snmp, system]` in `tacctl.yaml` names the
blocks in force; a file with no manifest entry is ignored and reported by
`check`, a manifest entry with no file is a finding.

Acceptance: permission and atomicity tests; the snapshot taken by every config
write copies `blocks/` beside `snmp/` and `backup restore` puts it back; a
scope rename and a scope removal move or refuse as `snmp/<scope>.yaml` do
(find how `snmp/` does it and follow it).

### B2. Junos `snmp` block

Grammar (one statement per line, `#` comments, blank lines, `set` only):

```
set snmp community <name> authorization read-only|read-write
set snmp community <name> clients <cidr> [restrict]
set snmp community <name> client-list-name <list>
set snmp trap-group <name> version v1|v2
set snmp trap-group <name> categories <category>
set snmp trap-group <name> targets <address>
set snmp trap-options <leaf> ...        (source-address: see "trap-source")
```

A `delete` line means "not managed on this device" and is kept, never
"must be absent" (decision 3). Refused by `check`: a name that is tacctl's own
(`TACCTL-SNMP` and the v3 names of the structured settings), a token off the
allow-list, a community with no `clients` or `client-list-name` (a world-open
community is a finding, not an error, with `0.0.0.0/0 restrict` allowed), and
`<secret>` placeholders. `check` lists the objects that become owned, the
statements that carry a secret, and the diff against the file in force.

Acceptance: a table-driven parser test with every refusal; resolution is per
object (community string, client-list name, trap-group name): a device block's
object replaces the scope's of the same key whole, a scope block's over the
default's, and the default level never carries a client or a target.

### B3. Rendering, compare, plan

The managed `snmp` section is the structured settings plus the resolved block
statements, so the walkthrough, the pull's compare and the plan stay one
renderer (`managed.go` rule: the statements are the live lines of what the
walkthrough prints; the test that every statement is in the walkthrough of the
same input keeps it). The labels of `internal/devconf/labels.go` number a
block's communities after the structured ones, in block order. New owned rows
in `plan/owned.go` (each with a row test): `snmp trap-group $` (ModeWhole),
`snmp community $` leaves of a block community (ModeWhole for a block
community, the rendered-leaves row of the structured one unchanged),
`snmp trap-options` (ModeSingle for the leaves allowed). A block's community
under another name on the device is `<other:N>` as before: kept and listed.
The `unmanaged` table of `internal/devconf/unmanaged.go` gains the shapes the
rows keep, with the test that keeps it in step with `owned.go`.

Acceptance: fixtures (synthetic) where the device has a block's community with
an extra client (deleted by its real name, section `differs`), has the other
community of the production shape (kept, `ok (+N unmanaged)`), lacks a block's
trap group (the plan sets it), and holds the trap group with an extra target
(deleted, because a block's trap group is ModeWhole); a legacy record (bare
`<secret>`) deletes nothing. Goldens change only where this says they must.

### B4. Verbs

`tacctl scope block <scope> <vendor> list|show|check|set|remove [<block>]`.
`set` reads a file (`--file <path>`) or standard input, runs `check`, shows the
diff and asks (`-y`), snapshots, writes once. Superuser only to set, remove,
edit and adopt; engineers read a block elided for their scopes
(`list`, `show`); `--reveal` shows the strings to a superuser and is logged
`secret-read kind=block name=<scope>/<vendor>/<block>` (the logger of
`completion_names.go`). The console's rules and the baseline tiers
(`internal/policy`, `internal/tier`) and the tab completion are updated in the
same change, and `make lint`'s man test must pass.

### B5. `edit`

Follows `visudo` and `sudoedit`: the editor ( `$VISUAL`, else `$EDITOR`, else
`editor`, else `vi`) runs as the INVOKING user on a 0600 copy in a 0700
directory, never as root, and the file is installed only after `check` passes,
after a confirmation, a snapshot and one atomic write. A failed check offers
to re-open the editor with the findings as comments at the top. The private
directory is removed afterwards (swap and backup files an editor writes land
there). Refused without a terminal. Test with a fake editor script.

*As built.* `internal/cli/blocks_edit.go`; `edit` and `adopt` share
`editFlow`, and `set`, `edit` and `adopt` share `review` and `install`
(`blocks_verbs.go`). The private directory is made under `/var/tmp`, the copy
is named `<scope|device>-<name>-juniper-<block>.txt`, the editor is started
with `syscall.Credential` (the account of `SUDO_UID`, verified as `tacctl ssh`
verifies it; a root process with no `SUDO_UID` is the person's own root session
and runs the editor as itself), and what it leaves is read as that user with
`O_NOFOLLOW` (regular file, at most `blocks.MaxSize`, theirs). A failed check
is offered back up to five times, the findings as `# tacctl: ` lines at the
top (numbered as the window is, stripped from every text before it is read). In
the login console (`TACCTL_CONSOLE`) the rule of `console system-shell tiers`
applies. **sudo's `env_reset` drops `VISUAL` and `EDITOR`**: both drop-ins
gain `tier.EditorKeep`, a `Cmnd_Alias` of the four lines that open an editor
and a `Defaults!` line that keeps those two variables for them (the way
`TACCTL_ASKPASS` is kept; no `SETENV`), `captureEditor` takes both out of the
sudo side's own environment, and `sudoArgv` carries them as command-line
assignments on those four lines for a caller whose sudoers rule does not
need the drop-in. `AskpassKeep` gains the two `adopt` lines.

### B6. `adopt`

`tacctl scope block <scope> junos adopt <device> snmp` reads the device's
`snmp` hierarchy live with the caller's login (the batch runner's transport;
nothing is stored: the raw text exists in memory and in the editor's private
copy only), drops what tacctl renders itself and the per-device identity
statements (`snmp name`, `engine-id`), and opens the result in the editor as
the draft to prune (decision 5). A device reached with `--login <local-user>`
is not in this package.

*As built.* `internal/cli/blocks_adopt.go` (the read: `chooseDevices` as a
pull selects, `newDevicePasswords`, `devssh.Dial`, NETCONF with the command
line as the fallback, `resultOf` for the words of a failure) and
`internal/blocks/adopt.go` (the draft, pure: `AdoptSNMP`, `AdoptSystem`);
`devconf.ReadHierarchy` reads `show configuration <hierarchy> | display set`.
The syntax is `scope block <scope> juniper adopt <device> <block>` and `device
block <device> adopt <block>`. The read is logged `secret-read
kind=block-adopt name=<scope>/juniper/<block>` whoever reads.

### B7. `system` block (Junos)

Statements: `system login message`, `system domain-name`,
`system domain-search`, `system time-zone`, `system name-server <addr>`,
`system ntp server <addr>` (with `prefer`, `boot-server`, `source-address`;
`authentication-key` a secret typed only where the device lacks it). A new
managed section `system`; additive only (decision 1): every statement is an
object, set when missing and extras kept and listed as unmanaged, with no
exclusive-list marker. The login message is a heredoc in the file
(`set system login message <<'EOF'` … `EOF`) rendered as the one statement
`set system login message "<line>\n<line>..."` (a newline between lines and
none after the last, `"` as `\"` and `\` as `\\`, leading spaces kept; a tab, a
control character or a non-ASCII character refused by `check`), and the
reverse conversion shows a device's `\n`-escaped string as the heredoc; the
round trip is the identity (test on a 22-line, 1,300-character message). The
plan notes that a human pasting a line longer than 1,023 characters into an
interactive terminal truncates it, and that `plan --plain` is the form for a
long message. Regions in the plan: after `snmp` and before `mgmt-acl`, never
last (`mgmt-acl` stays last).

### B8. Device-level blocks

`blocks/_devices/<name>/<vendor>/<block>` with `tacctl device block <device>
list|show|check|set|remove|edit`, the same code paths as the scope level with
the resolution of B2; a device in no scope is refused as elsewhere.

Storage (B8a, decided 2026-10-12): the directory is `_devices`, not `devices`:
a scope name starts with a letter, so `_devices` can never clash with a scope
and a scope called `devices` is legal. The device's lower case name is the
directory. The blocks in force are named in `tacctl.yaml` by
`blocks_device.<name with every '.' as '~'>.<vendor>: [snmp, system]` (the
break-glass hold's key rule, `conf.HoldKey`), one rule for both levels: a file
with no entry is ignored, an entry with no file is a finding. A device rename
moves the directory and the keys, a removal deletes both (its snapshot holds
them), and a new device (or the new name of a rename) that finds blocks of an
earlier device of its name is refused. `check` also reports a vendor directory
that is not the device's registry vendor and a device that is not in the
registry (orphans, never rendered). A rollback to 0.2.6 or older removes the
keys and leaves the files.

### B9. Closing

The helper script's region allow-list gains `system login message`,
`domain-name`, `domain-search`, `time-zone`, `name-server`, `ntp` and the
`snmp` trap-group statements (`check_region`); the walkthrough's Step 0
comment lines for domain, time zone and NTP are replaced by the block's
statements for a scope that has one; the bats suite, the container matrix and
`tests/diff/run.sh --all --against 0.2.6` are run; CHANGELOG items numbered by
theme, `man/tacctl.1`, `README.md`, `docs/release-notes-0.2.7.md`.

## IOS snmp block as built

The `snmp` block for vendor `cisco` (IOS and IOS-XE), with the verbs of the
Junos blocks (`scope block <scope> cisco
list|show|check|set|remove|edit|adopt`) and the device level. The `system`
block for IOS is the section after this one. Nothing of it has been pasted on
a device: the grammar and the stored forms are from the vendor's references,
the plan's report says so, and the changelog and the README call it not
lab-tested.

**Grammar** (`internal/blocks/snmp_cisco.go`, one statement per line, `#` and
`!` comments, ASCII, no tabs, at most 1,000 characters a line):

```
snmp-server community <string> RO|RW [<acl-name>]
snmp-server host <address> [version 1|2c] <community> [udp-port <n>] [<type> ...]
snmp-server enable traps [<type> [<subtype> ...]]
ip access-list standard <NAME>
 permit <address> [<wildcard>] | permit host <address> | permit any
no snmp-server community <string>
no snmp-server host <address> [version 1|2c] <community>
no snmp-server enable traps [<type> [<subtype> ...]]
no ip access-list standard <NAME>
```

A community string is 32 characters at most (IOS's limit) and has no blank,
`?` or quote. An access list name is letters, digits, `.`, `_` and `-`, never
all digits. An entry's address has no bit set under the wildcard (the network,
as a device prints it); `permit A`, `permit host A` and `permit A 0.0.0.0` are
one entry, written `permit host A`. Notification types are a table
(`IOSTrapTypes`), subtypes a shape; both are extended as a type is checked on
a device.

**Refused by `check`** (always with the line, never a string): tacctl's own
names (the structured community, `TACCTL-SNMP`, `TACCTL-VIEW`,
`TACCTL-GROUP`; and, at render time, the scope's management access list), a
numbered list, a read-write community with no list or whose list permits
`any`, a list with no entry, `deny` and `remark` entries, a trap host with
`vrf`, `traps`, `informs` or version 3, `snmp-server
contact|location|trap-source|engineID|user|group|view`, a placeholder, and any
other token. A read-only community with no list, or one open to `any`, and a
list the block only names are notes.

**Resolution** is per object, as for Junos: a community by its string, a list
by its name, a host by address and community, an `enable traps` line by its
words; a more specific layer's object replaces the less specific one's whole,
and a `no` line takes the less specific layers' object out. The default layer
carries no list entry and no host.

**Rendering.** The block's lines follow the structured settings in the SNMP
step (lists first, the entries indented by two blanks as the walkthrough
indents them), also when the scope's SNMP is not configured, under a comment
naming the block. They are the last lines of the managed `snmp` section,
marked as the block's by position (`Section.Block`); a host's line is a
secret statement (it names its community).

**Owned rows** (`internal/devconf/plan/owned.go`):

| Row | Mode | What it does |
|---|---|---|
| `ios.snmp.block-community` | single | the community line is retyped in place when it differs; never removed |
| `ios.snmp.block-acl` | whole, not ordered | a list the block defines: missing entries set, an entry the block does not state removed with a `no` line (IOS appends and may reorder, so the compare is by runs of one action, all `permit` here) |
| `ios.snmp.block-host` | additive | set when missing; a host of the same address and community with other options is retyped in place; the device's other hosts are kept |
| `ios.snmp.block-traps` | additive | set when missing; never removed |

The device's own communities, hosts, trap lines and lists are the shapes of
`devconf/unmanaged.go` (`ok (+N unmanaged)`), and `--converge` removes none of
them (an `<other:N>` or block community is guarded as a secret, and an
`enable traps` line is no kind of statement the cleanup removes).

**Stored forms.** A host is compared by its address, community and the set of
its options: `version 1`, `traps` and `udp-port 162` are not part of the
compared form and the types are sorted. A trap line the device prints
expanded (`snmp authentication linkdown linkup coldstart warmstart` for
`snmp linkdown`) satisfies the rendered line when it holds its type and its
subtypes; a line with no type is satisfied by any `enable traps` line.
(`coverTraps` in `devconf/ios.go`.)

**Plan, back-out and report.** The region order is that of `plan/ios.go` (a
list before the community that names it, the removals of a list's stray
entries after its adds). The back-out is the existing IOS one, `no` lines in
reverse; a community or host the plan replaced in place is typed again by
value where its string is one the rendering holds (the label maps to it), else
as a note. The report's words are "the SNMP block of scope '<scope>'" and the
section note says the block's lines were not checked on a device.

**Adopt.** `devconf.ReadHierarchy` has a cisco command table: `show
running-config | include ^snmp-server`, then `show running-config | section ip
access-list standard <NAME>` for each list a community names (a name that is
not a word of letters, digits, `.`, `_` and `-` is never put in a command;
the whole configuration is read once when `| section` is refused). The draft
(`AdoptIOSSNMP`) drops tacctl's own community and list, v3 and the identity,
repeats nothing the block (or, for a device, the scope's) already states with
the same statements, and names what a block cannot hold as `left out` lines.

**Reveal logging.** Every `show --reveal` of a block is logged
`secret-read kind=block name=<scope>/<vendor>/<block>` (or
`_devices/<device>/<vendor>/<block>`), whoever makes it.

**Not done, and why.** VRF forms of `snmp-server host`, `informs` and SNMPv3
hosts. Whether a device prints a trap line, a host and a list entry as the
stored forms above assume is not known until a paste is read back.

## IOS system block and trap-source as built

The `system` block for vendor `cisco` (IOS and IOS-XE) and the trap source of
both vendors' `snmp` blocks, with the verbs of the other blocks (`scope block
<scope> cisco list|show|check|set|remove|edit|adopt system` and the device
level). Nothing of either has been pasted on a device: the grammar, the stored
forms and the paste order are from the vendor's references, the plan's report
says so per section, and the changelog and the README call both not
lab-tested.

**Trap source.** `snmp-server trap-source <interface>` in the IOS `snmp`
block and `set snmp trap-options source-address <address>|lo0` in the Junos
one, which both refused it until now ("source address of a device's traps is
not a setting tacctl has"). One is in force at most. It is device-specific by
nature: a scope's block may state it (an interface name the scope's devices
share, `Loopback0`, or an address), and `check` notes that it is the same for
every device of the scope; a device's own block states another; the default
layer refuses it. The IOS interface is written in full (`Lo0` is refused: a
device stores it as `Loopback0`, so the short form would be typed again every
time) and compared without case; the Junos address is canonical IPv4 or IPv6
or the keyword `lo0`. Both render in the SNMP step after the hosts, compare
and plan as a single value (the typed statement replaces the old in place, no
`no` or `delete` line is emitted), and the device's own is kept (`notRendered`
shape) while the block states none. Owned rows: `ios.snmp.block-trap-source`
(new) and `junos.snmp.trap-options` (existing, ModeSingle). A `no
snmp-server trap-source` or `delete snmp trap-options source-address` line
means "not managed". `adopt` takes the device's own trap source into the
draft.

**Grammar** (`internal/blocks/system_cisco.go`, one statement per line, `#`
and `!` comments, ASCII, at most 1,000 characters a line):

```
banner login <<'EOF'
<text lines>
EOF
ip domain name <name>                  single (ip domain-name is read as it)
ip domain list <name>                  list (ip domain-list is read as it)
clock timezone <zone> <hours> [<minutes>]     single
ip name-server <address> [<address> ...]       list, one entry per address
ntp server <address-or-name> [prefer] [version <1-4>] [key <n>]
           [source <interface>]        list, one line per server
ntp authentication-key <n> md5 <string>       list, a secret
ntp trusted-key <n>                    list
ntp authenticate                       single boolean
no <statement>                         not managed here
```

The block is additive, as the Junos system block is: every statement is an
object, set when the device lacks it; a single value that differs is replaced
in place; a list entry is only added; nothing is ever deleted. Resolution is
per object (a name server and a domain-list entry by value, a server by its
host, a key by its number, a single value whole), a more specific layer's
object replaces the less specific one's, and a `no` line takes the less
specific layers' object out (`no ntp` takes every NTP statement out).

**The banner.** The text is a heredoc in the block file. It is rendered as
`banner login <d>`, the text lines and `<d>` alone on a line, where `<d>` is
the first of `^ ~ % # @ $ &` that the text does not contain; a text that holds
all of them is refused, as are a tab, a control character, a character that is
not ASCII, more than 20 lines, a line of more than 80 characters, and a line
that is `EOF`. The managed section holds the banner's lines as they are typed
(one element per physical line, which keeps the fixtures readable); the
walkthrough's blank-line filter leaves the text between the delimiters alone,
so a blank line of a banner survives. A device's banner is read by
`blocks.DeviceBanner`: the delimiter is `^C` (what IOS prints for Ctrl-C) or
one printable character, the text may begin on the opening line and end on the
closing one, and the line break after the opening delimiter and the one
before the closing delimiter are the delimiters' own; trailing blanks of a
line are not compared.

**Compared forms** (`internal/devconf/ios_system.go`, `ios.go`). The banner
is the statement `banner login <message: N lines, M characters, id
xxxxxxxx>` (the Junos login message's mark), so no text of it is in a stored
section, a report, a diff or `--json`. `clock timezone CET 1` and `CET 1 0`
are one statement (the minutes always present); `ip domain-name` and
`ip domain-list` are read as the current spellings and host names are lower
case; `ip name-server A B` is one statement per address; an NTP server is
`ntp server <host> [key N] [prefer] [source IF] [version V]`, its options in
that order, the host and the interface without case; an
`ntp authentication-key <n> md5 <string> [7]` is `ntp authentication-key <n>`
and a secret (compared by its number; the algorithm and the string are not);
`snmp-server trap-source` has its interface without case. Anything of a form
the code does not know (a `vrf` word, an option of another release) is kept as
the device printed it and compares as written. The statements the section
holds are the banner, `ip domain name|list` (any vrf form too), `clock
timezone`, `ip name-server` and every `ntp` statement, only for a scope whose
rendering has a system section; any other statement of those hierarchies
(`ip domain lookup`, `ntp master`, `ntp source`, `clock summer-time`) is
nobody's business of the section.

**Rows** (`internal/devconf/plan/owned.go`, each with a row test and a Kept
example):

| Row | Mode | What it does |
|---|---|---|
| `ios.system.banner` | single | retyped in place when its digest differs; never removed |
| `ios.system.domain-name` | single | retyped in place |
| `ios.system.timezone` | single | retyped in place |
| `ios.system.ntp-authenticate` | single | set when the device lacks it |
| `ios.system.domain-list` | additive | set when missing, the device's others kept |
| `ios.system.name-server` | additive | set when missing, the device's others kept |
| `ios.system.ntp-server` | additive | set when missing; a server of the same host with other options is retyped in place, the device's other servers kept |
| `ios.system.ntp-key` | additive | typed by value only where the device has no key of the number |
| `ios.system.ntp-trusted-key` | additive | set when missing, the device's others kept |

The unmanaged shapes of `devconf/unmanaged.go` name the same rows; the rest of
`ntp` (`master`, `source`, `peer`, `access-group`) is the device's own with no
row, and `--converge` removes none of it (its closed allow-list has no such
removal).

**Plan.** The section `system` follows `snmp` and precedes `mgmt-acl` in
`PlanOrder` for IOS, only when the rendering has one; every other output is
byte-identical. The lines are pasted in the order of the section's
statements, with the NTP lines ordered as IOS needs them: keys, trusted keys,
servers, `ntp authenticate` last (the report says so). A banner is one `Line`
whose text holds its physical lines; the region emitter writes them
consecutively (the first carries the line's index, the others none),
`pastedLines` counts them, and `--plain` is the statements as typed inside
`configure terminal` (it applies to IOS; it does not change what a terminal
takes on a line). `checkIOSRegion` has a banner state: entered at `banner login <d>`
(one delimiter character, nothing after it), every following line is text
(blank, indented or starting with `!`) until the line that equals `<d>`, no
label or comment can stand between, and a banner not closed before `end` is a
fault. A banner line longer than 255 characters (IOS's limit for a typed line)
is a warning; the grammar's 80 columns make it unreachable from a block, and
it guards a rendering that did not come from one.

**Back-out.** A replaced single value is typed again from the pull (`clock
timezone PST -8 0`, `ip domain name other.example.net`, `ntp server
192.0.2.123 version 3`, `snmp-server trap-source loopback1`); an added
statement is taken away as the device takes it: `no banner login`, `no ip
domain name`, `no clock timezone`, `no ntp server <host>`, `no ntp
authentication-key <n>`, `no ntp trusted-key <n>`, `no ntp authenticate`, `no
ip name-server <address>`, `no ip domain list <name>`, `no snmp-server
trap-source`. A replaced banner cannot be typed back (only its digest is kept): the back-out carries a note that names
`configure replace` with the archived or the startup configuration. The stored
back-out holds no banner text and no key.

**Report words.** The section's items say `the login banner of N lines, M
characters`, `the domain name is ...`, `the search domain ...`, `the time zone
is ...`, `the name server ...`, `the NTP server ...`, `NTP key N is set` and
`NTP key N is trusted`, `NTP authentication is on`, and, for an extra, `Left
alone (the system block only adds, it never removes)` with the removal line
that would take it away later. The section carries the note that its lines
were written from the references and not checked on a device.

**Adopt.** `devconf.ReadHierarchy(cisco, system)` runs `terminal length 0`,
`show running-config | include ^(banner|ip domain|ip name-server|clock
timezone|ntp )` and `show running-config | section ^banner login` (the whole
configuration once when `| section` is refused; the first command's own
banner line when a one-line banner is all there is). `AdoptIOSSystem` drops
what the block or the scope's block already states with the same value, takes
a multi-address `ip name-server` line apart, and leaves each `ntp
authentication-key` out with a `# left out:` line (the key string is never
adopted, whatever it looks like). The device's other banners, VRF forms,
`ip domain lookup`, `ntp master` and the like are counted as outside what the
block takes.

**Not done, and why.** The VRF forms (`ntp server vrf`, `ip name-server vrf`,
`ip domain name vrf`): the grammar refuses them and the device's own lines
stay unmanaged. IPv6 NTP servers (the keyword form differs between releases).
Other banner types (`motd`, `exec`). `clock summer-time`. A banner restored by
the back-out (only the digest is kept). Whether a device prints the lines as
the stored forms above assume, and whether it replaces a `ntp server` line of
the same host in place when it is typed again with other options, are not
known until a paste is read back.

## IOS restore point as built

`tacctl device config plan <cisco device> --restore-point[=<fs>]` (decided
2026-10-12). D100 stands: there is no timer region and no `--wrapper
replace`; the restore point is a file a person can go back to, offered beside
the `no` lines, and the report says it is not lab-tested (the block and the
`configure replace` alternative were written from the references and from the
12.4 and 15.6 notes of `0.2.4-spike.md`, and not pasted on a device).

**The block** (`internal/devconf/plan/restore.go`). Before the plan's region
and outside its `PASTE FROM HERE` banners, between `RESTORE POINT FROM HERE:
<device>` and `RESTORE POINT TO HERE: <device>` (the vendor's banner
character, `!!!!!`): one `copy running-config <fs>tacctl-<label>-<yyyymmdd-
hhmm>.cfg` and one empty line, or the one line `archive config`. `<label>` is
the device's name up to its first dot, limited to the characters `A-Za-z0-9_-`
and 32 characters (IOS file names are limited to about 63), the time is the
plan's `Header.Now` in UTC, so the name in the block, in the back-out and in
the kept back-out's stamp is one string. Comments above the block say: paste
it first and on its own at the privileged prompt, check `dir <fs>`; the file
holds the secrets in their own forms (protect it, delete it); it needs free
space; it is a file and no timer (D100); the empty line answers the
`Destination filename` prompt, a paste tool that drops blank lines turns the
closing banner into the file name, `file prompt quiet` turns the prompt off.

**The file system.** `--restore-point=<fs>` names it (`[a-z0-9]+:`; the
network file systems `ftp: tftp: rcp: scp: sftp: http: https:` and `null:` and
`system:` are refused, since their copy asks for more than one empty line
answers) and always makes the named copy. The bare flag takes it from the
pull: the extractor keeps the file system word of the `archive` / `path`
statement in the record (`Record.ArchiveFS`, `Extracted.ArchiveFS`; D107
described a note of the archive path, which the 0.2.5 extractor did not
keep), and the block is then `archive config`, which has no destination
prompt and no name to invent. A bare flag where the record has none is a
usage error (exit 2, raised before anything is planned) that says to name a
file system or to pull again; a record made before 0.2.7 has none either. Only
the word up to the colon is stored: a remote path (`ftp://user:pw@host/dir`)
never reaches the record.

**The alternative back-out.** The back-out's comments (the after-steps of
`--backout` and the kept text) gain `configure replace <file> force` (after
`archive config`: the newest entry of `show archive`, as a placeholder
`<that file>`), with the caveats from the spike worded as what was observed:
tried only with `archive` and a `path` configured; `copy <file>
running-config` only merges; the removal of `aaa new-model` was skipped in one
pass on 12.4, so AAA is undone with the `no` lines; delete the file and the
copies the replace leaves. The plan's after-steps name the restore point and
point to the back-out; for a plan with no line tacctl can type to undo it they
carry the alternative themselves, and so does the cleanup's after-text. The
kept back-out records the name (`StoredBackout.RestorePoint`, a `restore:`
line of its header; `--backout` prints `its restore point is <file>` in its
first comment line). A narrower plan from the same pull keeps the broader
back-out and says that it does not name this plan's file.

**Allowlists.** The region's allowlist (`CheckRegion`) is unchanged and still
refuses a `copy`; the restore block has its own, `CheckRestorePoint`: exactly
`archive config`, or one `copy running-config <fs>tacctl-<name>-<time>.cfg`
(a local file system) and one empty line, printable ASCII. The CLI's
`checkRegions` runs it before anything is printed. `golden_test.go`
(`withoutRestoreBlock`) lets the plain lines before the region be exactly
that block, and `restore_test.go` has the property that no other exec command
appears outside the region for every IOS fixture in every form.

**Decisions where the first design was silent** (2026-10-12).

- A named file system wins over the archive path: the person named the
  place, and a bare flag is the one that follows the device.
- `--restore-point` is refused with `--plain` (a plain file is the region's
  statements and has no room for a block that is not typed inside
  `configure terminal`) and with `--backout` (the kept back-out names the
  file its plan made; a recomputed one would carry another time). Another
  vendor is refused naming the devices, before anything is read.
- The flag takes its value after `=` only (a new `Optional` mark on the
  parser's `Flag`): a device name may follow the bare flag.
- A plan with nothing to paste has no restore block and no `restore_point`
  in its JSON; a cleanup that is the output's only region has the block
  before it, and its after-text names the file.
- `--json` `restore_point` is `{mode, file, command, file_system, note}`;
  `file` is absent for `archive config`.
- Nothing is a setting: there is no `device.config.*` key.

**Not checked without a device.** That a device answers the empty line to the
`Destination filename` prompt as assumed and accepts the name; that `archive
config` names its file as `show archive` lists it on every image; that
`configure replace <file> force` brings back what the plan changed on an image
other than the 12.4 and 15.6 ones of the spike, and what it does for the
statements the plan added with `no` forms (it was observed to skip the
removal of `aaa new-model` once); how a paste tool of a console treats the
copy's time. The first lab run is to be read against these.
