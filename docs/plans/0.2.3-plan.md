## 0. Summary

- **Goal:** ship what 0.2.2 deferred (the engineer tier, WP9.14, with D14's read-only `group junos` view), two operator features (Junos-style spaces at the console/shell prompt; rotation of a Linux host's provisioning account), and the Cisco/WTI lab acceptance; then the production run sheet for 0.2.2 → 0.2.3.
- **No store-format change** (a built-in `engineer` group waits for 0.3.0, D49), but **new keys and fields**, and an automated rollback tool (D50); among them these a 0.2.2 binary does not know: `space_completion` in `console.yaml` and `linux.engineer_sudo` in `tacctl.yaml` (`tier.<group>` is already a known key in 0.2.2 [V: `internal/conf/schema.go:126` per review]). 0.2.2's console parser rejects an unknown key and its `File.doc()` writes every setting on every console write, so a stray `space_completion` would make the console fall back to defaults, make console writes fail, skip the sshd drop-in at upgrade and fail `host sync` of the local host; `linux.engineer_sudo` makes 0.2.2's `backup restore` refuse a snapshot. Therefore (D34) the console writes `space_completion` only when it is off (which helps only until the console is written, because the engineer tier's `tiers.engineer` key already breaks a 0.2.2 parse; found by the WP10.4 review), `tacctl rollback 0.2.2` (D50) does the preparation automatically, and the release notes' "Rolling back" describes what it does and, for a manual rollback, says: run `tacctl rollback 0.2.2 --apply` (WP10.7a; it removes `tiers.engineer` and `space_completion` from `console.yaml` and `linux.engineer_sudo` from `tacctl.yaml`, among the rest) or, by hand, remove those keys first; take engineer groups at priv-lvl 15 out of the server's own scope (0.2.2 derives tiers from the priv-lvl, so they become superusers there and join `tac-superuser` on hosts at the next sync); then check out 0.2.2 and `tacctl upgrade`.
- **Order matters:** the engineer tier changed the Linux client script and the tiers sudoers, which is security-relevant and was never reviewed or integration-tested, so it is closed, reviewed and gated first (WP10.1-10.3). Space completion and rotation touch disjoint files and run in parallel after that.
- **Size:** 9 packages, ≈ 6-8 sessions, ≈ 3,500 lines (Go + bats + docs) on top of the 1,800 already on the branch.

## 1. Goals and non-goals

### Goals

1. **Close WP9.14** (§3): `host show --check` and `host show` know `tac-engineer`; the protocol-6 notes and bats; the read-only tier sees the Junos patterns (D29); one whole-branch review; every gate green.
2. **Junos-style spaces** (§4): a typed space refuses repeats, completes a unique fixed word, lists on ambiguity, never in free text or a paste; `console space-completion on|off`.
3. **Provisioning-account rotation** (§5): `tacctl host provisioner <name> rotate <user> (--key <file>|--password) [--remove-old] [--dry-run] [--yes]`.
4. **SNMP in the three walkthroughs** (§5b, user request 2026-10-08): `config cisco|juniper|wti` gain a full SNMP section: generic values from tacctl's own settings, a per-scope contact and per-scope allowed-client list (CIDR ranges, the server first, a final `0.0.0.0/0` restrict), per-device location and description, with the unfilled values listed. Reading a device's existing configuration and offering to set the gaps is 0.2.4 (D41).
5. **Lab acceptance carried from 0.2.2** (§6), starting with the one finding that can change code (tacquito's fall-through).
6. **Production run sheet for 0.2.1 → 0.2.3** (an artifact, not a repo file, per the handoff). **Production is on 0.2.1** (handoff, "Production"), so the sheet and the release notes cover 0.2.2's upgrade steps too: FreeRADIUS restarts once, the Cisco AAA block is re-pasted, custom Cisco templates are re-copied, WTI Service Name goes back to `wti`.

### Non-goals (0.2.3)

- Device configuration (pull, diff, apply, rollback), the password cache, WTI configuration, device-account rotation: 0.2.4-0.2.7.
- `group junos <g> list` as a read-only verb (D29 gives the read-only tier the same information through `group show`; the gate stays two words).
- Per-user `space-completion` (D33).
- Engineer-tier changes beyond closing WP9.14: no new engineer verbs except `host provisioner` (D37).
- TACACS+ accounting of console lines (backlog §1, optional).
- **Batch rollout of device configuration with concurrency and a global maximum** (user, 2026-10-08, for the large production Junos fleet): 0.2.4-0.2.5, recorded as a priority in `backlog.md` §0. **Design constraint on 0.2.3's code so it does not get in the way:** every walkthrough renderer (`internal/devices/{cisco,juniper,wti}.go`, including the SNMP and IP Tables blocks of D41/D42) takes one input struct for one device and returns text, with no CLI, terminal, global-state or clock access, so a batch can render per device in parallel and a push can reuse the same text; new tacctl.yaml/store reads happen once before rendering (WP10.5b/c review checks this).
- Reading a device's existing SNMP configuration, showing what is missing and offering to set it, and pushing it (D41): 0.2.4 with the read-only device configuration, together with backlog §3f's per-device overrides (the per-scope client lists moved into 0.2.3, D41). Pasting existing config into `config <vendor>` was considered and not chosen (a parser per vendor, thrown away once 0.2.4 reads configs).

| **D32** | **Space completion: mechanics** **[F, confirmed by the review; to finish in WP10.4]**. Implemented in `editor.key` (a `case key == ' '` after the Ctrl-R search cases, so a search query still takes spaces). A paste never reaches the key callback when **bracketed paste is in effect** (x/term returns before it for `pasteActive`, `vendor/golang.org/x/term/terminal.go:512-515`; the shell turns it on, `loop.go:301`); a terminal without it delivers pasted blanks as typed keys, which the rules below handle like typing. Rules, in order: inside quotes or after a backslash → insert; cursor at 0, right after a blank or right before a blank → refuse silently; **cursor in the middle of a word (the next character is not a blank) → insert the blank as typed, never complete** (completing there would turn `dev\|ice` into `device ice`); at a word's end the fixed candidates of the partial decide: an exact match present (`user` while `user-x` exists) → insert; exactly one → insert `Quote(word)+" "` (a following blank is reused, not doubled); several → list once (D33), insert nothing; none (free text or a typo) → insert. ### 3b. Baseline commands and privileges (user request 2026-10-08; WP10.6c, D52)

The user wants a good baseline of commands and privileges for every group, suitable for enterprise and provider-scale networks. Two independent reviews: an Opus audit of what ships today (done) and a Fable design (running). Audit result, ranked (Opus, 2026-10-08; items marked *lab* need a device):

- **BUGS in the shipped engineer preset (released in 0.2.2; production does not use the preset):** B1 most targeted Cisco denies only match the exact argument string, because tacquito anchors every regex at both ends and the patterns are prefixes (`^(…)\b`, `^config-key`, `trustBoundary`, the `do` list): `no aaa authorization config-commands`, `no aaa new-model`, `no username x`, `enable secret 0 x`, `ip ssh …`, `do reload in 5` pass; `TestEngineerCiscoRules` passes only because it does not anchor (fix: end every prefix with `( .*)?` and make the test wrap `^(?:re)$`). **Probe results (Sonnet, 2026-10-08; the installed tacquito on a loopback port with throwaway users, a 45-line RFC 8907 Python client, each row a live reply; the full table and client are in the session scratchpad and WP10.6c copies the client into `tests/tools/` as the lab permcheck harness).** (1) **A deny with a `match` list whose regexes all miss falls through** to the next rule, of the same name or not (`show` deny `^running.*` then `show` permit: `show version` permitted, `show running-config` denied); so the deny/permit pair design is valid and D40's open question is closed (WP10.6b is dropped). (2) **Anchoring:** `^` and `$` are added only when missing, so a pattern with a prefix form (`^crypto`) matches the bare argument string only (`show crypto` yes, `show crypto pki certificates` no) and `^crypto( .*)?` is needed for "and anything after"; **a top-level alternation without anchors is wrong: `crypto|trace` becomes `^crypto|trace$`, a prefix match on the first branch and a suffix match on the last (`show ip trace` and `show foo trace` were permitted, `show foo crypto` denied)**. (3) The regex is tested against the cmd-arg values only, space-joined, never the command word (`^show .*` on `show version` fails). (4) A rule with no `match`, or an empty `match: []`, decides at once, so a later rule of the same name is unreachable; `*` decides at once wherever it stands; a rule of another name is skipped; no matching rule at all denies. **D52 (decided 2026-10-08; the spec is `docs/plans/0.2.3-baseline-design.md`).** Fable's split: the shipped defaults get only the small safe changes (the `privileges.operator` rewrite, `terminal length|width` for readonly, `clear counters|line` for operator); the deny/permit pairs, the Junos deny sets, `ENG-CLASS` and the engineer list stay in the opt-in preset; `group reset` restores the shipped content and `group reset --preset` the role's. ## 10. Risks

1. **The engineer tier was never reviewed or integration-tested** and touches sudoers on every enrolled host: WP10.2 before anything else is built on it; any root-reach finding goes to Fable.
2. **Rotation locks the operator out of a host.** Mitigations: the proof is a fresh login in a new connection and the registry changes only after it; the old account is removed last, over the new one; `--dry-run`; the account is removed again when the proof fails (D38).
3. **Space completion changes typing for every console user at the upgrade** (default on). The CHANGELOG, the release notes and the production sheet say so and give `console space-completion off`.
4. **A space at a live-name position costs a sudo call** (cached); acceptable, noted in the usage.
5. **tacquito may not fall through** on a missed match: the preset's Cisco list would change; found early by D40.2.
6. **`--password` needs a terminal**; without one the command refuses, and `--key` is the scripted path.
7. **Two packages edit `internal/tier/tier.go` and the generated sudoers/permits goldens** (10.1 touches the table indirectly, 10.5 adds a row): 10.5 starts from the merged 10.4 and regenerates goldens last.
9. **SNMP vendor syntax is written from references**, not lab-tested until WP10.6 (WTI's menu steps are [A]); the CHANGELOG says "not lab-tested" for any step the lab does not confirm.
8. **Rolling back to 0.2.2 is not a plain checkout** while `space_completion` is off or `linux.engineer_sudo` is set (§0): the release notes carry the steps.
