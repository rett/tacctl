## L1 texts

- Operational prompt `admin@lab-sw1> `, preceded by a `{master:0}` line on a
  virtual chassis (blank line before it). Configure prompt `admin@lab-sw1# `,
  preceded by `{master:0}[edit]` (or `[edit system login]`). A standalone
  device prints no `{master:N}` line.
- `configure` echoes `configure `, prints `Entering configuration mode`, a
  blank line and the location line. `exit` prints `Exiting configuration
  mode`.
- `configure exclusive`: `warning: uncommitted changes will be discarded on
  exit` then the entering text. Refused while another session holds it:
  `error: configuration database locked by:` + `  admin terminal pts/0 (pid
  84557) on since 2026-10-13 20:02:28 AKDT` + `      exclusive
  {master:0}[edit]`.
- `configure` (shared) while exclusive is held: enters, with `Users
  currently editing the configuration:` and the holder's line. `configure
  private` while exclusive is held: `warning: changes cannot be committed
  while 'configure exclusive' is active`.
- `commit check`: `configuration check succeeds`.
- `commit confirmed N comment "..."`: `configuration check succeeds`,
  `commit confirmed will be automatically rolled back in N minutes unless
  confirmed` (`1 minutes` for N=1), `commit complete`, then the banner line
  and the location line.
- `rollback 1` prints `load complete`; `commit` after it prints
  `configuration check succeeds` and `commit complete` and removes the banner.
- `commit` with no private changes in a private session: `warning: no
  private changes to commit`.
- A space in a line typed at the configure prompt triggers completion on a
  pty; commands are sent without terminal editing games (the transport sends
  whole lines; the spike's `run show system rollback compare` failure was
  that command not existing).

- **Rescue line (first run).** `parseHistory` refused the `rescue <time>
  by <user> via <how>` line Junos prints at the end of `show system commit`
  when a rescue configuration is saved; fixed in `0.2.8-35` (the second run
  read it).
- **Defect A (items 1, 2, 4).** `CompareText` (`internal/devconf/plan/
  compare_text.go`) refuses the context line Junos prints for an unchanged
  entry of a list when an entry is added beside it, e.g.

  ```
  [edit snmp]
      trap-group zz-tacctl-tg { ... }
  +   trap-group zz-tacctl-staged {
  ```

  So every check of a delta that adds an entry to a list the device already
  has (a name server, an NTP server, a community, a trap target, a filter
  term) fails closed at the compare, and the gate fails closed on such a
  staged change with the wrong reason. A whole new object with no sibling
  and a delete parse.
- **Defect B (item 6).** `Reconcile` settles `by root via other` over
  tacctl's commit from the delta of a fresh read against **today's**
  rendering (`internal/cli/device_apply.go` `settle`): no delta is
  `applied`. When the rendering changed after the pending commit, a
  rolled-back commit is recorded `applied` (or the other way round). The
  pending commit's own change (its compare) is what to settle against.
  The settled result is also neither printed nor audited, and the run's
  own check or apply overwrites it at once.
- **Item 5 trigger.** `--server 192.0.2.250` adds a second server beside
  the switch's own (the plan leaves the existing one alone), so the fresh
  login still works, and the same delta changes the authentication order
  and accounting outside `zz-tacctl-*`: not run. The refused login was made
  on the server side instead; the transaction path is the same.
- **Registry.** The restored entry's fields are identical; it now stands
  last in `devices.yaml` (the file differs in order only). The pull record
  is the collect's (`over ssh`, no serial until the next pull).
- **Small surprises.** `sync`'s facts table prints the record's time in UTC
  where `device show` prints local time, and its `LOGIN` column reads `-`
  for the invoking user's own login.
