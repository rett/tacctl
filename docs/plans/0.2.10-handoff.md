## Scope of 0.2.10

Work starts from `develop` once 0.2.9 is merged.

- **Device accounts and break-glass rotation:** a new local account on the
  devices, proven by a fresh login, the target switched, the old account
  removed last; passwords generated and shown once. Decide first whether a
  scope's break-glass hash is stored (a block) or generated and shown once
  (`backlog.md` section 0, the 0.2.10 row).
- **A NETCONF service setting for Junos** (decided with the user): three
  states, default `leave`. `enable` renders and plans `set system services
  netconf ssh` (with the optional connection-limit and rate-limit),
  `disable` plans `delete system services netconf`, `leave` plans and
  compares nothing (today's behaviour). Per scope with a per-device
  override, layered as SNMP and the blocks are: `scope netconf <scope>
  enable|disable|leave`, `device netconf <name> ...`. The apply allow-list
  admits only those exact `system services netconf` statements; everything
  else under `system services` stays on the never-list (D133). It needs its
  own review and a live run on the lab switch, and supersedes `device
  config enable-netconf` (D93 of `apply-deferred.md`).
- **Unattended drift detection:** a timer running `device config pull
  --stale` needs a credential no person types. Designed as a read-only
  service account on the devices (a key held by the tacctl server, proved
  and rotated like the provisioning accounts); `devssh` authenticates with a
  password or keyboard-interactive only today.
- **Later, not 0.2.10:** apply over NETCONF as the second transport
  (`apply-deferred.md`; the transport interface and `Confirms()` exist), IOS
  and WTI apply, ASA (`asa-deferred.md`).

## Working rules

- Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides
  important design questions. Subagents never commit; the coordinator reviews,
  merges, renumbers CHANGELOG items and commits.
- Commits and pushes only when the user asks; push only the branch being
  worked on; merges into `develop` and `master`, tags and releases only when
  the user says so. No Claude attribution in commit messages.
- No private names (hosts, addresses, users, home paths, domains) and no
  description of any installation's state or deployment in repo files or commit
  messages: use roles ("the dev server", "the lab switch") and `example.*`,
  `192.0.2.x`.
- Never act against the production host and never connect to a production
  device: prepare the files and let the user apply them.
- Every user-visible change gets a numbered CHANGELOG item and updates
  `man/tacctl.1` and the matching `docs/` page in the same change.
- Gates: build, gofmt, `go vet`, `make lint`, Go tests (`internal/cli` needs
  `setsid -w ... < /dev/null`, a scratch `GOCACHE`), bats as the invoking
  user, the diff corpus against the previous release, the container matrix,
  `groff -k -ww`. Tests sandbox host paths.
