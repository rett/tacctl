## Scope of 0.2.10

Work is on `feature/0.2.10`, from `develop`. The plan is
`docs/plans/0.2.10-plan.md` (D145-D153, draft).

- **A NETCONF service setting for Junos:** three states, default `leave`.
  `enable` renders and plans `set system services netconf ssh` (with the
  optional connection-limit and rate-limit), `disable` plans `delete system
  services netconf`, `leave` plans and compares nothing (today's behaviour).
  Per scope with a per-device override, layered as SNMP and the blocks are.
  The apply allow-list admits only those exact `system services netconf`
  statements; everything else under `system services` stays on the
  never-list (D133). A change to the service always goes over the command
  line (the verification depends on the service). It supersedes `device
  config enable-netconf` (D93 of `apply-deferred.md`).
- **Apply over NETCONF** as the second transport of D129: `devapply`'s
  `Transport` gets a NETCONF implementation, the driver is unchanged. The
  default is `auto` (NETCONF where the device answers and confirms, else the
  command line), with `--transport` and `device.apply.transport`.
  `device config rollback` from history stays deferred.
- **On hold, not 0.2.10 for now:** device accounts and break-glass rotation
  (decide first whether a scope's break-glass hash is stored or generated
  and shown once, `backlog.md` section 0), and unattended drift detection on
  a service account (`devssh` authenticates with a password or
  keyboard-interactive only today).
- **Later:** `device config rollback` (D86), IOS and WTI apply, ASA
  (`asa-deferred.md`).
- **Lab:** the lab switch is not used until it is released for testing; the
  plan's section 6 lists what the live runs must settle.

## Working rules

- Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides
  important design questions. Subagents never commit; the coordinator reviews,
  merges, renumbers CHANGELOG items and commits.
- Commit when appropriate (a coherent unit of work that has passed its
  gates); ask before pushing, and push only the branch being worked on;
  merges into `develop` and `master`, tags and releases only when the user
  says so. No Claude attribution in commit messages.
- No private names (hosts, addresses, users, home paths, domains) and no
  description of any installation's state or deployment in repo files or
  commit messages: use roles ("the dev server", "the lab switch") and
  `example.*`, `192.0.2.x`.
- Never act against the production host and never connect to a production
  device: prepare the files and let the user apply them.
- Every user-visible change gets a numbered CHANGELOG item and updates
  `man/tacctl.1` and the matching `docs/` page in the same change.
- Gates: build, gofmt, `go vet`, `make lint`, Go tests (`internal/cli` needs
  `setsid -w ... < /dev/null`, a scratch `GOCACHE`), bats as the invoking
  user, the diff corpus against the previous release, the container matrix,
  `groff -k -ww`. Tests sandbox host paths.
