Vendor detection (D260, WP17.10, `vendor-detection.md`) was added to
this release on 2026-10-23: `device add`, `device check`, `device
vendor --from-device` and `device discover --snmp` read the vendor from
the device by SNMP; lab captures of a Junos switch, a WTI unit and three
Cisco images are rows of `TestDetectVendor`, and `cisco`, `juniper` and
`wti` are offered (`wti` by its enterprise alone: its sysDescr is generic
Linux text). Separable, like WP17.6 and WP17.7. The six gaps the plan's
review note under D260 found against the code are settled as "Settled in
WP17.10" there records: the flag of `discover` is `--snmp` (`device list
--probe` stays a TCP connect), and `device check` makes three SNMP
exchanges per device (name, location, identity; six round trips per device
under v3, which `check --all` runs 16 at a time), not the single read the
plan assumed.

The attended enroll and remediation workflow (D261-D272, WP17.11 to
WP17.15, `enroll-workflow.md`) was added the same day, in place of a
0.2.18 release: `device enroll <address>... | --discovered` runs scan,
a host-key acceptance per device confirmed by typing the device's name
after comparing the one key shown with the console (no `-y`, no
accept-all, no trust on first use, no fingerprint typed or pasted;
`--host-key` for one address is the only form without a terminal),
vendor and name from the device with a question for what cannot be
read (`other` is an answer: the device is registered and its chain
ends there, exit 0), register at once under the name typed (one
snapshot for the run), pull, then the device's own configured name
takes precedence (an automatic registry rename, no question, nothing
written to the device; kept with the reason when the name is taken,
generic, invalid or the device is held), plan, and for Junos the
offer of the apply review (not with
`--json`, which ends at the plan); `--differs`, `--name` and `--ip`
join the
selectors of `device config pull|diff|plan|apply|list`; `apply --pull`
pulls first; the apply review is answered per device by its name (any
declined device is exit 1), and `--confirmed -y` stays for superusers,
marked `mode=scripted` in the lines. Every host-key acceptance is an
audit line with the person, the device, the algorithm, the fingerprint
and the `sid=`. Junos is the only vendor written to. `collect` and
`onboard` accept keys the same way (WP17.15, separable). The dependency
order and the cut order are sections 5 and 6 of the plan: the audit
packages and vendor detection are the base, the workflow packages stand
on them.

The plan rests on a read-only audit of the write paths made 2026-10-21
against `54435e7` (`0.2.17-plan.md` section 7). The 0.2.16 work in
progress touches `internal/hosts`, `internal/cli/{backup,linux,user}.go`
and `internal/snapshot`; WP17.1's mechanical change of the `Logger` call
sites is made after 0.2.16 is merged, not against the half-edited files.

Excluded by decision: a local audit store of tacctl's own, a hash chain,
remote shipping, logging the read verbs (section 8 of the plan keeps
them as options with a recommendation each). No new device write path,
no credential, nothing scheduled or automatic.

Direction: every operation is started by a person; tacctl holds no device
credential and runs nothing on a schedule (`0.2.12-plan.md` section 2).
The log is syslog through `logger`; where it goes from there is the
site's concern, and no repo file describes any installation's collector.

## Decisions as built

- D257 `audit.strict` ships, default off on a new install and on upgrade
  alike. `tacctl config audit-strict on|off` sets it (WP17.6b), is never
  refused by it, and is how it is turned off while `logger` is down. Under
  strict a secret reveal whose `secret-read` line cannot be written is
  refused before the secret is shown (`nothing was shown.`, exit 1).
- D252 `--reason` is logged as typed: it is the hold's justification and
  the field an auditor asks for.
- D250 the ssh and console session lines stay beside the central pair
  (four lines per session).
- D246 a root shell logs `user=root origin=root` with no login identity;
  refusing a root shell for write verbs is a policy change outside this
  release.
- WP17.7 ships: `scope secret <s> set` prompts or reads `--stdin`, and
  `user add|passwd --hash -` reads the hash from standard input.
- D262 pins one key, the first in type order (ed25519 first), and shows
  that one for the comparison; it is accepted by typing the device's name
  back. The others are listed as offered and pinned after a check of their
  own (`device hostkey <name> accept`).
- D260: the flag of `discover` is `--snmp`, since `device list --probe` is
  a TCP connect. `cisco`, `juniper` and `wti` are offered by detection.
  The `vendor-differs` notice is not acknowledgeable.
- D267: `--stale --differs` combine as AND on `pull|diff|plan|apply`
  (`device config list` keeps its state words as alternatives).
- D253: `group edit` with several keys writes one central pair and one
  detail line per key changed.
- D252: the console DENY line's `first=` word list (the console's own words
  beside tacctl's verbs) lives in `internal/console`.
- D264: the plan `device enroll` prints is the `--no-secrets` plan (each
  secret a marked line); `device config plan <name>` prints the region to
  paste.
- D263: the name offered at the key's question is the full SNMP sysName,
  lower-cased, not its first label.

## Working rules

- Model routing: Opus reviews, Sonnet and Haiku implement, Fable decides
  important design questions. Subagents never commit; the coordinator
  reviews, merges, renumbers CHANGELOG items and commits.
- Commit when appropriate (a coherent unit of work that has passed its
  gates); ask before pushing, and push only the branch being worked on;
  merges into `develop` and `master`, tags and releases only when the
  user says so. No Claude attribution in commit messages.
- No private names (hosts, addresses, users, home paths, domains) and no
  description of any installation's state, deployment or log collector
  in repo files or commit messages: use roles ("the dev server", "the
  collector") and `example.*`, `192.0.2.x`.
- Never act against the production host and never connect to a
  production device: prepare the files and let the user apply them.
- Every user-visible change gets a numbered CHANGELOG item and updates
  `man/tacctl.1` and the matching `docs/` page in the same change.
- No secret, hash, password or community string in any log line, test
  golden or doc example; the no-secret test of D255 is a gate.
- Gates: build, gofmt, `go vet`, `make lint`, Go tests (`make gate-go`,
  which runs `internal/cli` under `setsid` with no stdin and ends with one
  `GATE-GO PASS|FAIL` line: start it with the Bash tool's
  `run_in_background`, never with a trailing `&` or a `pgrep -f` wait, and
  count only that line), bats as the
  invoking user, the diff corpus against the previous release, the
  container matrix, `groff -k -ww`; the `test` workflow on the pull
  request. Tests sandbox host paths, and a test must not read a path of
  the machine it runs on. A test that needs the process environment, the
  lock wait or a package-wide registry calls `serial(t)` first; the
  others run in parallel (`hooks_test.go`).
- A release: `docs/releasing.md`. The release branch is pushed and a pull
  request opened to `master` so the Go tests run before the tag;
  `release-reproducible` runs on the tag by `workflow_dispatch`.
