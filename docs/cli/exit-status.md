# Exit Status and Environment

[Documentation](../README.md) › [CLI reference](README.md)

Exit status (`man tacctl`, EXIT STATUS, has the detail):

| Status | Meaning |
|---|---|
| 0 | The command did what it was asked, or showed what there was to show. A confirmation answered no cancels it with nothing changed and exits 0 for the removals and `store rollback` |
| 1 | The command refused or failed and said why on standard error: a value that does not fit, a name that does not exist, a caller whose tier does not allow it, a check that found a problem (`config validate`, which with `--json` prints its object first; `console check`, `device check`), a device that could not be read, compared or planned (`device config pull|diff|plan`), a device `device config apply` failed, rolled back or left pending (and a review that was not answered, and an apply that applied none of its devices and found none already applied: `--confirmed --yes` that skipped them all), an unknown subcommand (one error line, the closest verbs and a pointer to the help). Nothing was changed unless the message says what was |
| 2 | Wrong arguments for a verb that checks them itself (`store show`, `store import`, `store rollback`), an unknown backend id, or an action the backend does not provide; wrong arguments of `device config pull|diff|plan|apply|shapes|list|forget` (`apply` without a terminal and without `--confirmed --yes`, and `apply --hold --json`, included); `device config apply --check --exit-code` when a device needs a change; `device config diff --exit-code` when a device differs, `device config plan --exit-code` when a device needs a change |
| 3 | A backend command was refused because a rendered file holds a hand edit that it would discard, or `store import --check` could not prove the import safe; nothing was written |
| 126 | sudo could not be run to re-run tacctl as root, or `tacctl-console` was given an argument it does not accept |
| 127 | sudo is not installed, and tacctl was not run as root |
| 130 | Interrupted at a prompt (Ctrl-C at a password prompt), or a `device config pull`, `diff --pull` or `apply` stopped by Ctrl-C (the first stops starting devices, a second cuts the running ones off; an apply's transaction in flight finishes under the first, and under the second a candidate is discarded and a pending commit cancelled where the window allows, else reported `PENDING`); a pull writes nothing on a device |

`tacctl ssh` and `tacctl device ssh` end with the status of the ssh they run, `tacctl shell -c` with the status of its line.

A command that changes state writes its status to the audit log as the `status=` of its `cmd end` line, with a `result=` word ([Audit log](../security/audit.md)): `ok` for 0, `interrupted` for 130, `denied` when a verb refused the caller (the status is the verb's own, 1), `aborted` (status 2) when tacctl itself panicked, `failed` for any other status.

Environment: tacctl reads `SUDO_USER`, `SUDO_UID` and `SUDO_GID` (the person behind sudo: the tier gate, the target of `passwd`, the scopes an engineer reaches; the pair is checked against the passwd database and a mismatch denies every command), `HOME` (the shell's history), `USER` and `LOGNAME` (the console's session log), `SSH_CLIENT`, `SSH_TTY` and `SSH_CONNECTION` (set by sshd), `SSH_AUTH_SOCK` and `DISPLAY` (handed to the ssh that `host`, `ssh` and `device ssh` run), `VISUAL` and `EDITOR` (the editor `scope block ... edit|adopt` and `device block ... edit|adopt` run as you; sudo's environment reset drops them, so the sudoers drop-ins keep them for those four command lines only), `TACCTL_CONSOLE` (the console's session marker, only ever used to tighten), `TACCTL_COLOR`, `NO_COLOR` and `TERM` (whether output is styled: only on a terminal that is not `dumb`; `TACCTL_COLOR=always` or `never` wins, else a non-empty `NO_COLOR` means never; the sudoers drop-ins keep the two variables so the choice reaches the root process, and without a drop-in the terminal alone decides; the console decides by its terminal only, or by `console color`), `TACCTL_HELP_KEY` (read by the bash completion script, not by tacctl: the key that prints the help of the words before the cursor; see [the help key](shell.md#shell-completion)), `TACCTL_ASKPASS` (set by a shell or console session whose password cache is on, for the lines that use it: `<socket>:<token>`, dead when the line ends; see [Password cache](shell.md#password-cache)), `TMPDIR` (where tacctl stages the private copies it renders, checks or sends while it works, removed on every path; default the system temporary directory, `/tmp`; sudo's environment policy may replace it) and `TACQUITO_SRC` (the tacquito source clone, default `/opt/tacquito-src`). `tacctl man` passes only `TERM`, `LANG` and `LC_*` on to `man`, `groff` and `less` and ignores `PAGER`, `MANPAGER`, `LESS`, `LESSOPEN`, `LESSCLOSE`, `MANPATH`, `MANOPT`, `MAN_*` and `GROFF_*` (see [Manual page](shell.md#manual-page--tacctl-man)). The variables that move tacctl's paths and clock for the test suite (`TACCTL_ETC`, `TACCTL_STATE_DIR`, ...) are not an interface; `tests/README.md` describes them.
