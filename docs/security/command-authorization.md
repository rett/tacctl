# Per-command authorization

[Documentation](../README.md) › [Security](README.md)

Restrict which commands a group can run on Cisco devices, enforced live by Cisco IOS via TACACS+. Junos devices do not use these rules: the server sends them each group's own `deny-commands` and `deny-configuration` sets at login (`tacctl group junos`; see [Juniper Junos](../devices/junos.md#juniper-junos)). **RADIUS has no per-command authorization on Cisco**: over RADIUS a group's users are limited only by the privilege level, login class or access level the Access-Accept carries (`tacctl status`, `config render` and `backend enable` name the groups whose rules RADIUS does not enforce). Tacctl ships these defaults; a fresh install needs no seed step:

- `superuser`: unrestricted `*` catch-all (permit).
- `operator`: permits `show`, `dir`, `ping`, `traceroute`, `terminal`, `ssh`, `telnet`, `undebug`, `exit`, `logout`; default **deny** catch-all. **An operator may not interrupt service, even intermittently, and the `engineer` is the escalation**: nothing that clears a table, an entry, a counter or a line (`clear ...`), captures traffic (`monitor capture ...`) or sends traffic at a rate is permitted. `ping` and `traceroute` take a host and the one-line extended options, in any order, each number inside a bound the rule checks: `ping [vrf <name>] [ip|ipv6] <host> [source <addr|if>] [size 1-9999] [df-bit] [repeat 1-1000] [timeout 1-10] [data <hex>] [validate]`, `ping mpls ipv4|pseudowire <target> [<vc-id>]`, `traceroute [vrf <name>] [ip|ipv6] <host> [source <addr|if>] [numeric] [probe 1-10] [ttl 1-255 [1-255]] [timeout 1-10]`, `traceroute mpls ipv4|pseudowire <target> [<vc-id>]`. A value past a bound (`repeat 1001`, `repeat 2147483647`, `timeout 0`, `size 10000`, `probe 11`, `ttl 256`), `sweep` (MTU testing is `size` with `df-bit`), another keyword and anything after the options (a `;` and a second command) are denied. **The interactive dialog is denied**: a bare `ping` or `traceroute`, or a protocol keyword with no host (`ping ip`, `ping ipv6`, `ping vrf <name> ip`, `ping mpls`, `ping clns`, `traceroute ip`, ...), makes IOS ask its questions (repeat count, timeout, sweep range) at the device, and what is typed there is neither authorized by the server nor accounted, while the one-line forms carry the same choices as arguments that the rule checks and the accounting records. A broadcast or multicast address as the host is a residual risk no regex can close. The `engineer` runs every form, unbounded, the interactive one included. The `vrf` and `mpls` forms are expected to be level-15 commands on a device and are not lowered, so an operator's level does not reach them either. A rule bounds a command's arguments only while the server answers: on a RADIUS device, and with the server unreachable, the device's privilege level alone decides, and neither verb is lowered, so an operator there runs the basic `ping` and `traceroute` of IOS's own level-1 command set and nothing the rule would have allowed beyond them (whether an image accepts `repeat` or `timeout` at that level depends on the image; tacctl cannot change it). That is the strict side of the trade-off: lowering the verbs would hand every form to every user whenever the server does not answer. `commands.operator` and `commands.readonly` rules stored in `/etc/tacctl/tacctl.yaml` (the role preset stores them) are kept until `tacctl group commands reset <group>` puts the shipped rules back. The role preset of 0.2.3 stored `show` denies the shipped rules do not have; `tacctl group reset <group> --preset --only commands,junos` puts the preset's current values back and keeps them. `tacctl upgrade` drops a list that is exactly what 0.2.3 shipped, and names a stored one that still permits `clear`, `monitor` or a `ping` or `traceroute` with any arguments.
- `readonly`: permits `show`, `dir`, `ping`, `traceroute` (the same bounded forms as the `operator`), `terminal length|width`, `exit`, `logout`; default **deny** catch-all. It is the account for monitoring and backup systems such as SolarWinds NCM, which only read and compare configurations: nothing in it permits a change, a hop (`ssh`, `telnet`), `debug`, a capture or a `clear`, and `terminal monitor` stays out (it can leak debug across sessions). Log such a system in at the level that reads the configuration (no `enable` step: it would use the device's local enable secret and skip per-command authorization).

The roles nest: every command `readonly` may run, `operator` may run; every one `operator` may run, an engineer may run (`tacctl group preset roles`, see [Group commands](../cli/group.md#group-commands--tacctl-group)); and the superuser may run everything. The shipped rules permit all of that but for one deny in front of the `show` permits of `readonly` and `operator`, `show running-config view full` (unfiltered, it shows every key); the other denies that keep secrets out of reach are the role preset's.

View the shipped defaults with `tacctl config defaults`; inspect a single group with `tacctl group commands list <group>`. Rules live under `commands.<group>` in `/etc/tacctl/tacctl.yaml`; tacquito.yaml's per-group `commands:` block is rendered from that source on every change. `tacctl group commands reset <group> [--dry-run] [--yes]` puts one group's rules back to the shipped defaults (what `tacctl group reset <group> --only commands` does, for any group): it prints the rules it removes (`-`), adds (`+`) and moves (`~`) and the default action, asks `Apply these changes to the command rules of group '<group>'? [y/N]` (`--yes`, no terminal, `--dry-run` and `already canonical` as for `group reset`), takes the usual snapshot, renders and restarts the backends once, and logs `group commands reset name=<group> by=<user>`. A group with no shipped rules (a custom group, or `engineer`) has none afterwards: its override is removed, never stored as an empty list. It takes no `--preset` (the role preset's rules come with `tacctl group reset <group> --preset`) and keeps the lockout guard of `group reset`: a group at the same priv-lvl without rules gets a `*` permit rule, and a group left without any warns. Superuser only.

`tacctl group commands seed` re-applies the shipped rules. It is a recovery tool for when you have customized the rules and want to start over; a fresh install already has the shipped defaults in effect.

Build rules manually:
```
tacctl group commands default operator deny
tacctl group commands add operator show --action permit
tacctl group commands add operator ping --action permit
tacctl group commands add operator terminal --match '^(length|width)( .*)?$' --action permit
```
A rule's `name` is compared literally to the TACACS+ `cmd=` word. `--match` regexes are tested by tacquito against the command's **arguments only** — the space-joined `cmd-arg` values after the word, so `show running-config` is tested as `running-config`, never as the full line. A regex that repeats the command word (`^show .*$`) can never match and is rejected by `tacctl group commands add`, and so is an empty one (tacquito skips it), an invalid one (tacctl checks with Go's RE2, as tacquito does) and one with a comma (the stored rule line separates matches with commas; write `\x2c`); omit `--match` to cover any arguments. tacctl renders every regex as `^(?:regex)$`, so it has to match the whole arguments string, without `<cr>`, and a top-level alternation stays together (`crypto|trace` means `crypto` or `trace`, nothing else): `--match '^crypto'` matches `show crypto` only; write `--match '^crypto( .*)?$'` to cover `show crypto pki certificates` too. `group commands add` and `config validate` warn about a prefix form that lacks `( .*)?` and about a rule that cannot be reached because an earlier rule of the same name has no `--match` (it decides every command first) or follows the `*` catchall. A stored rule written for tacquito's own anchoring of a bare alternation (`crypto|trace` became `^crypto|trace$` and matched more than it said) now matches only what it says, so a rule that relied on the old reading stops matching. `tacctl upgrade` heals any stored override that still carries the dead shape of a regex that repeats the command word, which denied every `show` to operator and readonly users.

Rules are tried in order, the order `tacctl group commands list <group>` numbers in its `#` column: a rule without `--match` decides, and one whose regexes all miss falls through to the next, so a deny with `--match` placed before a permit of the same name works. `add` puts a rule before the catchall, or before the first rule of another name with `--before <name>`, or first with `--first`:
```
tacctl group commands add operator show --match '^crypto( .*)?' --action deny --before show
```
`tacctl group commands remove <group> <name>` refuses when several rules share the name; pick one with `--match` (the rule's regexes, all of them, in order) and `--action`, or pass `--all` to drop them all.

The trailing `*` catchall encodes the default action. Once any group has rules, `tacctl config cisco` emits `aaa authorization commands <level> default group TACACS-GROUP local` for every privilege level a group uses, and `aaa authorization config-commands`, so IOS asks tacquito per command, configuration commands included. A level where some group has no rules gets the line commented out instead, naming the group and the fix (`tacctl group commands default <group> permit`): emitted, it would have the server deny that group every command.

When you add the first rule to a group, tacctl auto-seeds a `* permit` catchall onto sibling groups at the same Cisco priv-lvl so their users aren't accidentally locked out.
