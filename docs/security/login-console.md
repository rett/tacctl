# Login console

[Documentation](../README.md) › [Security](README.md)

**On the tacctl server itself, every tacctl user's login shell becomes the login console once the server's accounts are synced** (`tacctl host enroll --local`, then `tacctl host sync <name>` after any change); nothing changes for anyone before that sync. A console user who logs in over ssh gets a `<host>> ` prompt that runs tacctl commands (as `sudo tacctl …`, so the [tiers](tiers.md) apply line by line) and `tacctl ssh` to the registered devices of their scopes, and nothing else: no system shell, no file transfer, no port forwarding (superusers excepted by default: `console forwarding tiers`). `ssh <server> 'user list'` runs one tacctl line; `scp`, `sftp` and `rsync` are refused.

- **Who gets it.** Every tacctl user of every tier, with no switch: the next `host sync` of the server sets the console as the login shell (`usermod -s`) and the sshd drop-in forces it; `tacctl console show` lists each user's effective shell and why. To keep a user off the server, take the scope off the user. The engineer tier has the console or no login on this server: an account whose console cannot be provisioned (the `tacctl-console` link is missing) gets `/bin/bash` only if it has the system shell (a superuser always; others when a superuser opened it to their tier or to them) and `/usr/sbin/nologin` otherwise, an engineer included, as does an account whose tier is none. sshd's drop-in `/etc/ssh/sshd_config.d/00-tacctl-engineer.conf` (its own file, written at every sync of this server even when the console is not installed, named to be read before the console's) closes every forwarding and tunnel for the engineers whatever shell they have (agent forwarding follows `console agent-forwarding`); `console check` verifies that file on its own and also looks at the engineers: each member of `tac-engineer` has the console or a nologin shell, sshd closes forwarding for them, and every member of `tac-superuser` that is a tacctl account is a superuser-tier user (root excepted; a removed user whose UID is in tacctl's range is named red; a local administrator outside the UID range is listed as not a tacctl account and the check stays green). Lowering a tier (`group edit … tier`, `group edit … priv-lvl`, `user move`, `user rename`, `user disable`, `user remove`, `user scope … remove|replace`, `group remove`, `group preset roles --force`, `group reset`) syncs this server's accounts at once; when that fails the command says `Members of '<group>' keep their old groups on this server until: tacctl host sync <server>`. An engineer keeps this lockdown (no system shell, no forwarding) even when `tacctl.yaml` cannot be read and the gate treats them as an operator.
- **A required password change.** A user who must change the password (`tacctl user require-password-change`, which `user add` and an administrator's `user passwd` do by default; never a superuser) gets, when the console starts, the notice `A password change is required of your account.` and the password change dialog straight away: no device accepts the login until the password is changed, nor any enrolled Linux host but this server (its next `host sync` expires the account there, SSH keys included), and nothing else runs in the console. Every other line, `help` and the other words of the console included, is refused (`A password change is required: nothing runs here until it is made but 'passwd' (and 'exit').`, status 1), Tab and `?` list the change only, and Up and Ctrl-R recall no earlier line. Once the password is changed the session goes on as any other. A console that cannot read the answer (sudo refuses, the store cannot be read) cannot tell whether a change is required and holds a user who is no superuser the same way, without the dialog; a superuser, known by the system group `tac-superuser`, is never held by a read error. Ctrl-C in the dialog ends the session; a wrong current password or a rejected new one leaves the locked prompt, where `passwd` tries again and `exit` leaves. `ssh <server> 'user list'` and a batch are refused the same way, and a plain shell or `ssh <server> tacctl ...` meets the same refusal in the command line (only `passwd`, `version` and `help` run). The user must be able to get here: a user with no login on this server is never required to change the password (see [User Commands](../cli/user.md)). The sessions and refusals are in the log (`console password-change`, `console DENY ... reason=password-change`).
- **Break-glass.** Local accounts that are not tacctl users (root, the administrators who installed the server) are never touched, so they keep their shells and their local passwords; a tacctl user has no plain shell on the server.
- **sshd's drop-in is the key line.** `Match Group tac-console` in `/etc/ssh/sshd_config.d/tacctl-console.conf` sets `ForceCommand /usr/local/bin/tacctl-console` (every login, remote command and subsystem, the sftp server included, reaches the console, which takes the client's command from `SSH_ORIGINAL_COMMAND` and lets only one tacctl line through), `DisableForwarding yes` with `AllowTcpForwarding no`, `AllowStreamLocalForwarding no`, `X11Forwarding no`, `AllowAgentForwarding no` and `PermitTunnel no` (agent forwarding only with `console agent-forwarding enable`). For each tier of `console forwarding tiers` (default: superuser) a block before it, `Match Group tac-console Group tac-<tier>`, sets `DisableForwarding no`, `AllowTcpForwarding yes` and `X11Forwarding yes`: sshd takes the first value it finds, so those users can `ssh -X`, `-L`, `-R`, `-D` and `-J` through the server (still into the console, still by password) while everyone else stays closed. Forwarded ports on the server listen on loopback only (`GatewayPorts no` in the console's block) unless `console forwarding gateway-ports enable` adds `GatewayPorts clientspecified` to the tier blocks: an `ssh -R 0.0.0.0:8080:host:80` to the server then listens on every address, and the console's `tacctl ssh` takes `-g` and a bind address on `-L` and `-D`; anyone who reaches the server can connect to those ports. Then `PubkeyAuthentication no` (a key login would bypass TACACS+), and `ClientAliveInterval 300` / `ClientAliveCountMax 2`. Every change is checked with `sshd -t` and undone when sshd refuses it; sshd is reloaded otherwise. `/etc/ssh/sshd_config` must include `sshd_config.d/*.conf` (Debian, Ubuntu and RHEL 9 do). `tacctl console check` (operator and up) asks `sshd -T` what it applies to a console user and warns in red when anything is off; `console show` does the same.
- **`system-shell`.** The console word `system-shell` starts the user's own system shell, logged. Superusers always have it; readonly and operator users do not until a superuser opens it for the tier (`tacctl console system-shell operator enable`) or for one user (`tacctl console system-shell user <name> enable`; a user's setting wins over the tier's, in both directions; an enable lasts only while the user stays in the tier they had when it was set, so a demotion does not leave a shell behind); engineers never have it. Only a superuser sets it; the operator tier and up read it (`tacctl console system-shell`, `... <tier>`, `... user <name>`, `... path`) and `console show` shows each user's access and why.
- **Password cache.** `console password-cache tiers` says which tiers may keep a user's network password in the session's memory; for an allowed tier it is off until the user types `password-cache on` (`console password-cache on`) at the prompt, which saves the choice for later sessions and starts it in that one. A user sets only their own choice; a superuser sees and clears the others' with `console password-cache user`. See [the shell](../cli/shell.md#password-cache).
- **Pasted lines.** A line that starts with `tacctl`, `sudo tacctl` or `/usr/local/bin/tacctl` runs as the line without it (the console takes only the rest); see [the shell](../cli/shell.md).
- **Logged.** Sessions, refused commands and system shells go to syslog (tag `tacctl-console`), every line to sudo's log, and every `tacctl ssh` session with `console=<session>`. A refused `-c` string logs its first word (`first=`) only when it is a verb of tacctl or a console word; any other word, which can be a password typed at the prompt, reads `first=- len=<n>`.
- **Undoing it.** `tacctl host unenroll <server>` gives tacctl's accounts `/bin/bash` back and removes the drop-in and the `/etc/shells` line; so does `tacctl uninstall`, which never leaves an account with a shell that is about to disappear.

The [tiers sudoers rules](tiers.md) must be installed for readonly and operator console users: without them their lines are refused by sudo.
